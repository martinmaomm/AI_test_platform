# 性能节点单条 Docker 命令接入

用户于 2026-09-18 确认：网页输出真正的一条 `docker run`，容器自动注册并持续运行，不再复制长 Bash 引导脚本。不改变压测引擎、项目权限或现有节点身份。

## 安装与身份

- 固定多架构镜像摘要，Docker 自动选择 Linux amd64/arm64；发布版本 0.2.1，协议 2、Locust 2.43.3 和压测运行时不变。
- 命令参数为 `start --server HTTPS_URL --node-id UUID --token TOKEN [--ca-sha256 HEX]`；一次性令牌仍为 15 分钟，网页关闭后不回显。
- 首次启动注册并保存身份，随后进入原心跳/执行循环。重启优先使用卷中身份，不再消费命令中的注册令牌。
- 容器名、身份卷由节点 UUID 确定。单条 `docker run` 不自动删除同名容器；已安装节点使用 `docker restart`。
- 状态目录保存平台/节点/CA 指纹绑定，独占运行锁防止同一卷并发接管；损坏、身份不符、符号链接或不安全权限立即拒绝。
- 注册失败保留令牌摘要和失败状态。同一令牌不会因 Docker 重启策略重复提交；未注册节点的新令牌可再次尝试。长期凭证不出现在 Docker 参数或日志中。

## 信任与隔离

- 私有 CA 不嵌入镜像，不复制整段 PEM；网页只提供可信管理端计算的 SHA256 指纹。
- 新增公开 GET/HEAD `/api/v1/performance-agent/install/ca.pem`，仅提供已验证的 CA 公共证书，不返回配置、凭证或私钥。
- 首次无 CA 时，在隔离的无认证下载通道取回公开证书：固定同源路径、禁止重定向/代理、限制大小与时间。指纹及 CA 合法性核对成功后，注册和心跳均恢复严格的证书链与主机名校验。下载阶段不能发送令牌。
- 未提供 CA 指纹时只使用系统信任，不自动降级。卷内缓存证书每次使用仍校验指纹。
- 非 root、只读根文件系统、独立身份卷、临时 tmpfs、去 capabilities、禁止提权、资源与日志上限；不挂 Docker socket，不开节点入站端口。
- 用户已接受一次性令牌可见于终端历史与 Docker 容器参数；该令牌使用后失效，长期身份只保存在专用卷中。

## 发布与切换

- 先分别构建、运行验证并审计两个架构的镜像，再公开发布；只用已验证成员组成多架构索引，匿名读取并分架构拉取成功后写入 manifest 的 `registry_index_ref`。
- 网页缺少有效索引时明确提示不可用，不回退长脚本；新发行目录与旧版本隔离。
- 0.2.0 与 0.2.1 使用同一协议、引擎和运行时，平台明确允许已有 0.2.0 节点继续工作，不自动升级。
- 后端/Celery/网关/控制器在确认空闲后更新运行配置，保留旧发行文件和本地配置备份。

## 验收范围

1. 后端命令只包含单条 Docker 调用、固定索引、正确转义与短指纹；管理权限和令牌不回显不变。
2. CA 端点仅返回公钥；错误指纹、非法证书、重定向、超大响应不发送注册凭证。
3. 本机隔离 HTTPS fixture 验证真实 Docker 首次注册、心跳、重启复用身份、错误 CA、401 后不重复注册；不访问业务目标、不发压。
4. 前端安装向导复制、说明与构建；发布后验证实际配置生成的单条命令和网关证书端点。
5. Ubuntu/Unraid 目标网络的下载速度和实际登记独立验收，不用本机 Docker 结果冒充远程验证。
