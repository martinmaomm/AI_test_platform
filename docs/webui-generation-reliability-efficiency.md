# UI 脚本生成：任务恢复与探索效率

## 用户看到的流程

仍然是一个智能体、一个浏览器会话、按顺序探索并保存 Python 草稿，不拆成多个互相交接的业务智能体。

- 任务运行时独立写入 worker 心跳，长时间等待模型不会被直接判为失联。
- 打开详情或历史列表时，发现已领取任务的心跳超时，会保留草稿和轨迹并标为中断。只处理当前有权限查看的记录；历史列表仅处理本页。
- 没有 worker 领取的排队任务仍显示排队，不会被自动重放。
- 中断或失败后可以编辑已有草稿，也可以选择“基于轨迹整理脚本（不启动浏览器）”。
- “确认现场后继续探索”会要求填写已完成操作、现有数据和剩余工作，再确认启动新浏览器。未保存的本地修改、运行中的调试/修复、待审核的修复候选会阻止恢复。
- 新浏览器没有上一会话的登录状态。智能体会结合恢复说明先检查现场，按需登录、查询，再继续剩余步骤；平台不会自动执行已保存 Python 或重放整条流程。模型仍可能判断错误，恢复前应检查测试数据。
- 同一记录最多恢复探索 3 次，与补充信息恢复共用已有次数限制；仅整理脚本不启动浏览器，不计入该次数。原始证据保留，不把不同浏览器尝试的事件编号合并。

“继续探索”不等于“继续运行脚本”。草稿完整性检查也不等于业务测试通过，仍应进行真实调试。

## 可靠性边界

任务版本和 Celery task ID 一起校验检查点、阶段更新、最终结果与异常结果。旧 worker 的晚到结果不能覆盖新一轮草稿。派发失败只终止尚未被 worker 领取的对应版本。

检查点保存失败时停止探索，权威草稿回到最后成功持久化的版本；未保存候选仅作为诊断信息保留，不通过终态写入偷偷替换旧稿。

每次探索使用独立的 `backend/logs/playwright-mcp/<生成ID>.<尝试ID>.script-v5.trace.jsonl`，不会截断上一轮文件。恢复信息、心跳与归属信息放在现有 JSON 字段中，无需数据库迁移。

失联判断是在访问详情/历史列表时进行，不是常驻自动恢复服务；关闭页面后不会因为本功能自动启动浏览器。单次心跳数据库异常会记录警告并在下一周期重试。

## 减少模型往返与重复文本

1. 关键点击、导航、按键完成后，通过同一个浏览器读取工具附带当前页面观察。若同一批工具的下一项就是页面读取，则不重复自动读取。失败动作不触发自动读取，观察失败也不重放动作。
2. 自动观察同样经过工具预算、停止检查和完整轨迹回调。可顺序连续填写已经观察过的独立字段；联动、加载中、观察失败或信息缺失时仍需再次观察。
3. 首次保存或整体重写使用 `save_script_draft`；局部修改使用 `patch_script_draft`，要求修订号相同且原文本唯一匹配。一批修改全部匹配后才进入原有质量检查和持久化流程。失败保留原草稿，不自动清除待补全标记。
4. 需要准确代码时可按行调用 `read_script_draft`。平台插入的待补全标记也能被读取，不要求模型猜测当前源码。
5. 只压缩发给模型的上下文：省略旧的完整工具轮次，保留原始用户输入、最新页面和最近两轮，另附当前草稿版本及完成/剩余进度。工具调用与响应成组保留，截断内容有明确提示，不将省略内容当作“页面不存在”。
6. 历史恢复提示不再重复附带多份完整草稿和嵌套的历史记录；完整日志、事件和草稿仍保存供人工核对。v5 获取纯浏览器证据，不再经过 v4 最终路径定稿计算；仍有调用者的 v4/API 功能保留。

“技术信息”中展示自动观察、局部保存及累计模型消息字符数。字符数不是 token 或账单；记录不包含系统提示/工具 Schema 的费用，不能据此承诺真实节省比例。新请求附加检查点也有少量开销。

## 配置与生效

在 `backend/.env` 可选设置，默认值如下：

```dotenv
WEBUI_GENERATION_HEARTBEAT_INTERVAL_SECONDS=15
WEBUI_GENERATION_STALE_TIMEOUT_SECONDS=120
WEBUI_EXPLORATION_AUTO_OBSERVE=true
WEBUI_EXPLORATION_CONTEXT_CHARS=48000
```

心跳超时至少为心跳间隔的 3 倍。上下文字符数是软上限（范围 12000–200000）：原始输入、最新页面和最近两轮必须保留时允许超限，不强行截断必要的工具调用。

以上不是 `LLM_TIMEOUT_SECONDS` 单次请求超时，也不是页面探索总时限，不会增加模型/浏览器调用预算。自动观察如果不适合特定 MCP 配置，可设 `WEBUI_EXPLORATION_AUTO_OBSERVE=false`，由智能体按需主动读取；模型上下文压缩和局部保存仍然有效。

更新代码/环境变量后重启后端和 Celery worker。开发前端由 Vite 热更新；生产前端重新构建。无需运行迁移、清空数据库或重新下载浏览器。

## 验收边界

离线回归覆盖归属竞争、失联保护、重复提交、恢复权限与本地草稿冲突，以及真实 LangChain 图中的工具串行、自动观察回调、预算和上下文裁剪。前端恢复确认使用真实浏览器和模拟 API 验证，未向被测站点或模型服务发送请求。

实际模型是否少做重复操作、定位是否准确、同一场景最终节省多少 token，仍需要在重启服务后用真实模型和测试网站验证；离线回归不能代替这一部分。
