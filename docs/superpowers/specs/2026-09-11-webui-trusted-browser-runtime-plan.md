## 第一批：浏览器观察与状态基础

### 接口与替换方式

通过项目现有的 `MCP_PAGE_DIAGNOSTICS=1` 受控 MCP 启动入口，为 UI 生成替换可见 HTML/文字工具的读取实现。不修改 npm 缓存中的包，不另起浏览器；关闭该 opt-in 的其他流程维持原有工具行为。

两种读取工具共享一份浏览器采集逻辑。页面整体观察优先当前可见对话框、表单、主体控件，再提供导航及文字。支持根据 selector 局部补读；目标隐藏、不存在或有多个匹配时明确返回不能确定，不能拿第一个结果当作唯一目标。

采用有界等待采样，不能依赖永远不会结束的 network-idle。稳定只表示采样窗口内的观察稳定，不证明服务端写入完成。无法等到稳定时返回明确状态，不自动重复点击。

### 内部数据约定

现有 `PLATFORM_BROWSER_DIAGNOSTICS_V1` 帧追加 `observation`，由平台产生，不要求大模型填写：

```text
version: 1
page_url / page_title / scope
fingerprint: 全局可见语义状态的 SHA-256
settled / truncated / notes
elements: [{tag, role, name, id, type, placeholder, visible, enabled, container}]
text: [可见文字]
```

观察体有大小与数量限制，字段按结构裁剪并标明缺失；不得把截断后的缺失视为页面不存在该元素。返回值不输出输入框当前密码。URL/标题、真实控件状态和文字变化可以改变指纹；时间戳、截图文件名、工具调用 ID、读取格式、局部观察范围不能改变指纹。不同作用域读取使用同一个全页状态口径。

`truncated` 指本次观察范围的完整性。全页较大而局部表单完整时，局部读取可以返回 `truncated=false`；全局指纹采样受限以 `global_state_partial` 单独注明，不能让模型因为全页过大而无休止重读已经完整的局部区域。

Python 在去掉传输帧之前先提取并校验观察信息，再生成模型可读的紧凑摘要。错误诊断里的可见/可用状态不得与传输帧一起丢弃。自动观察和显式读取共用同一处理路径，不重复计算浏览器调用或改变串行顺序。
