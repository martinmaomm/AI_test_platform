# 原性能节点升级入口

已确认范围：用户在原节点上手动升级，平台提供完整可复制指导，复用节点身份，不需要重新登记。平台和远端节点不自动执行升级；本次不修改 Agent 0.4.0、协议 3 或已发布镜像。

## 页面与接口

旧版本节点增加“升级节点”操作，管理员安装信息接口返回 `installation.upgrade`：目标 Agent、固定镜像、节点 UUID、平台 URL、公开脚本 URL 与 SHA256。身份失效、运行未结束、状态未知或脚本缺失时不给出可执行参数。新安装命令仍用于未注册节点。

页面区分原部署方式：Docker 命令、Unraid 模板、Compose。容器名不能从节点名称猜测；Docker 允许填写实际容器名，留空由本机脚本确认唯一身份。复制之前重新读取节点状态，关闭页面或切换节点后丢弃迟到结果。Compose 只操作用户指定服务，Unraid 继续沿用原模板。

公开 GET/HEAD 入口只返回静态 Python 代码，拒绝查询参数，不包含令牌或机器配置。下载允许私有 CA 引导，但 SHA256 必须匹配管理员页面值才执行。独立 Bash 子进程隔离 `set -e`、trap 和变量，所有参数按 shell 规则引用；不上传本机 `docker inspect` 或身份文件。

## 本机升级工具

选择 Linux root + Python 3.8 标准库 + 现有 Docker CLI，避免增加 Docker SDK 或启动挂载 Docker socket 的辅助管理容器。CLI 与 Unix socket API 使用同一 daemon，兼容 Docker 20.10 的 `docker context inspect`。

升级分为只读检查、停止替换和启动确认：

1. 使用原安装器同节点互斥锁，识别唯一容器，核对持久身份、实际 `run/start` 命令、平台和 CA 绑定。
2. 拉取固定镜像并读取实际 Agent 版本，确认空闲、持久卷和配置可克隆。原 `run` 无新版绑定文件时按原环境与身份核验，保留其启动方式。
3. 将旧容器 restart policy 设为 no，停止并复查执行状态，以备份名称保留；按原配置和实际挂载源创建同名容器。
4. 新容器通过早期存活检查后恢复原 restart policy，提示回平台确认新版心跳。失败时先确认新容器已停止清理，再恢复旧容器；不能确认停止时保留旧容器停用，避免两个同身份 Agent 同时运行。

自动工具只支持独立容器、单动态 bridge 网络。由 Compose/Swarm/Unraid 管理、静态 IP、复杂网络或不完整身份的容器明确拒绝，回原管理工具操作。不会删除身份卷、改写旧安装器配置、重新注册或自动安装系统依赖。

## 验收与边界

覆盖后端权限/元数据、真实 Bash 参数和哈希失败保护、真实 Vue/Chrome 指导、假 Docker 故障场景以及隔离真实 Docker 迁移。真实容器只访问临时模拟平台，不能触碰已有用户容器或向业务目标发压。

复制命令不是平台维护锁。用户需要在升级期间停止安排新任务；本机脚本检查已接受的执行与报告状态。容器存活不等于平台在线，最终以新版心跳和单用户验证为准。

部署仅合入平台代码/前端，并重启后端与 Caddy 激活公开静态入口，无数据库迁移或镜像重发。出现问题可回到原平台代码；远端旧节点保持现有状态，由用户自行选择时机执行升级。
