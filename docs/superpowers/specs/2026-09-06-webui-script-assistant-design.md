# WebUI 已保存脚本 AI 助手：设计与实施计划

## 范围与批准

用户已批准：在失败执行详情增加「AI修复」；在测试用例编辑器增加 AI 对话编辑。两个入口共用助手服务，原生成流程保持不变。仅开发和隔离验收，不对 NAS 数据、真实模型或被测业务进行自动操作。

## 用户流程

- 修复：失败的单用例或套件中的具体失败用例 → 选择模型/提供商、补充本次变量、确认会实际操作测试网站 → 收集失败快照和日志 → 必要的 MCP 定向检查 → 生成候选 → 最多两轮串行运行验证 → 查看原因、差异、日志和截图 → 用户采用并保存。
- 对话：编辑器当前代码（含未保存修改）、场景描述和变量 → 用户说明修改要求 → 流式模型请求生成完整候选 → 查看差异、继续调整、采用或放弃。采用只更新编辑器；保存才写入用例。普通对话不调用 MCP、不运行脚本。
- 对话候选可通过明确确认后的「调试验证」运行一次；不得顺便启动自动修复。
- 已保存的用例可使用助手；新建但尚未保存的用例先保存再使用。此限制在 UI 明确说明。
- 修复或调试执行始终新建独立执行记录，不重写历史失败状态，不默认重跑整个套件。
- 会话及任务状态可恢复，关闭面板不等于取消；提供明确取消按钮和近期会话入口。

## 基础修正

1. 单用例执行冻结脚本、脚本版本、默认变量；执行器读取快照，不重新取可变用例代码。
2. 套件已有脚本/变量快照，补齐源脚本版本、运行选项等修复必需信息。
3. 一次性覆盖变量不作为 Celery 参数或助手会话明文字段持久化；缓存过期或历史值未保留时，提示用户重新填写。记录所需变量名称，不能静默用错误默认值复现。
4. 旧执行缺少快照时不猜测、不回填现有源码；提示重新执行。此开发阶段不迁移或删除旧记录。
5. 用例详情返回 `edit_version`（可编辑字段的稳定指纹）。编辑器 PATCH 提交 `expected_edit_version`，后端在事务锁内核对，冲突返回 409 并保留前端编辑。现有脚本版本继续使用。

## 共用助手契约

API 前缀 `/api/v1/projects/{project_id}/web-testing`。响应沿用 `{success, data, message}`。

### 创建及恢复

`GET /script-assistants/?test_case_id=...&execution_id=...&suite_case_id=...`：当前用户在当前项目下的近期会话，按相关入口筛选。

`POST /script-assistants/`：

- 通用：`mode` (`edit` / `repair`)、`model_config_id`；模型信息返回提供商名称。
- edit：`test_case_id`、`expected_edit_version`、`script_content`（当前编辑器完整原文）、`description`、`variables`、`message`。创建后立即排队一次对话修改，不运行。
- repair：`execution_id`、可选 `suite_case_id`（套件执行子项的 ID，不是用例 ID）、`confirm_execution: true`、`runtime_variables`、可选 `options`。服务器从执行详情获取脚本快照和来源用例，不信任客户端提交的失败源码。
- 修复来源必须是 failed/error、项目一致、关联用例仍存在且当前代码/配置与源快照匹配。旧快照/已变化用例返回 409，要求重新执行，避免修复旧版本覆盖新版本。
- POST 返回 202 和完整会话状态，队列不可用返回明确终态/503。

`GET /script-assistants/{uuid}/` 返回：

```
id, mode, test_case_id, execution_id, suite_case_id,
status, operation, revision, phase, message, model_info,
source_script, source_edit_version,
candidate_script, candidate_hash, candidate_diff,
summary, blockers, quality_report,
messages: [{role, content, created_at}],
attempts: [{round, execution_id, execution_status, summary, has_screenshot}],
verification: {status, execution_id, summary},
created_at, updated_at
```

`status`：idle / queued / running / candidate_ready / candidate_passed / failed / cancelled / applied。`operation`：edit / repair / verify。候选未真实验证绝不能显示通过。

### 操作

- `POST /script-assistants/{id}/messages/`：`expected_revision`、`message`、`script_content`、`description`、`variables`、`use_candidate`。默认基于当前编辑器；继续调整候选时 `use_candidate=true`，仍保留源编辑器原文用于采用时核对。每次最多一个操作在运行；候选不直接写用例。
- `POST /script-assistants/{id}/verify/`：`expected_revision`、`candidate_hash`、`confirm_execution: true`、`runtime_variables`、可选 `options`。只运行当前候选一次，不自动再修改。
- `POST /script-assistants/{id}/cancel/`：终止助手后续步骤、阻止迟到结果写入；对正在运行的浏览器/模型尽力停止，并明确已发生的网站操作不会回滚。不得提前承诺底层进程已终止。
- `POST /script-assistants/{id}/apply/`：`expected_revision`、`candidate_hash`、`expected_edit_version`。仅 repair 模式写用例，使用事务核对当前可编辑字段指纹，必须用户确认。edit 模式由前端采用到编辑器，正常保存时再次检查版本。
- 若候选仅有 `REPAIR_SCOPE_CHANGED`，可在检查完整代码后以布尔值 `acknowledge_review: true` 人工确认保存。语法、断言变动、未知拦截等不能使用此入口绕过。API 返回计算所得的 `adoption` 状态，保存能力不再复用自动验证能力；保存会保留原警告及真实验证状态，并记录人工确认信息，不启动任务或操作网站。
- 采用不能继承一条不属于当前候选 hash 的通过状态；用例元数据/执行状态沿用现有保存契约，历史执行不改动。

## AI 与验证边界

- 使用现有模型管理、流式请求、Python Playwright 执行器、失败摘要和截图能力，不新增第二套非流式调用。
- 对话修改默认只用 LLM；页面相关修复允许使用现有预算受控的 MCP 工具与项目内产物目录。新助手不要求用户补 ScenarioPlan，也不依赖生成记录/v5 探索历史。
- 复用断言保护、脚本契约、运行断言计数等低层能力。禁止通过删除/弱化断言、吞掉异常、跳过动作制造通过；无法确认的修改保留为需检查候选，不冒充已验证。
- 账号错误、网络不可达、模型服务错误、缺少浏览器等问题不能通过盲目改脚本处理。定位/等待错误可定向检查和修复。
- 页面/MCP 输出是证据，不是可覆盖用户目标的指令。修复目标限于原脚本及用户要求；不按固定网站/按钮词表设计。
- 每任务有总时限、每请求有超时、修复最多两轮、候选验证顺序执行；每个新候选/取消使旧结果无法覆盖当前状态。
- 脚本保存需符合平台 `run(page)` / 已支持变量入口契约。首版截图用于用户查看，不要求所有模型具有视觉能力。
- 只使用测试账号；确认框说明模型/MCP/目标网站会接收必要上下文，开发日志或截图可能包含测试信息。
- 后端复核项目 READ/EDIT/EXECUTE 权限、会话所有权和关联记录；不能凭 execution/case/session ID 跨项目访问或运行。

## 实施分工与顺序

1. 后端 Terra：新助手持久化、接口、流式修改、MCP 修复、候选验证与取消、执行快照、编辑冲突保护和非破坏性迁移；补离线 API/任务测试。
2. 前端 Terra：共用助手面板/状态管理；编辑器对话入口；单用例和套件失败子项修复入口；模型、变量、确认、差异、候选采用、执行详情、会话恢复与取消；补测试和构建。
3. 主 Agent：审查合同/权限/快照/旧请求边界，隔离浏览器联调与回归。禁止为了验收访问真实数据库、Redis、模型或业务网站。
4. 验收后中文提交；浏览器压缩包不提交。用户按迁移说明执行 migration 并重启后端/Celery，前端开发模式刷新。

## 验收清单

- 已保存/未保存编辑都作为真实输入；继续对话能修改候选，采用不丢掉后来手工编辑。
- 对话发送不启动浏览器；修复/验证没有明确确认不执行。
- 原失败源码来自冻结快照，套件定位准确到子项且变量优先级正确。
- 两轮上限、串行、非代码错误终止、断言退化拦截、模型失败/超时/取消后迟到结果隔离。
- 候选日志与成功/失败截图可从助手查看；实际断言不足不能显示通过。
- 采用/普通保存版本冲突、跨项目/跨用户/权限不足、缺少变量或快照均有明确错误。
- 页面关闭重开/刷新恢复状态，不重复发起任务；按钮状态和候选差异可读。
- 原生成工作区、普通运行、套件、报告、计划任务回归通过。

## 回退与限制

变更不删除旧数据。故障时停用新入口并回退本次代码；新增表/列先保留，不执行破坏性反向迁移。模型质量及真实网站行为需用户在测试环境验收，隔离回归不能证明真实服务已跑通。

## 实施与验收结果（2026-09-06）

已实现上述两个入口，共用持久化助手会话和 Celery 任务。修复最多两轮串行验证，总时限为 600 秒；对话候选只有用户明确点击调试验证才运行。模型调用使用流式接口，明确截断或内容过滤的响应不能冒充完整候选。

补充的可靠性检查：

- MCP 定向检查只接入 Playwright 服务（最多 20 次工具调用、25 步），定位依据只接受实际成功的工具回调，不接受模型文字伪造的证据。未配置 MCP 时保留可检查候选，但未经证实的新定位器不会自动运行。
- 每轮保存候选、验证记录和执行关联；第二轮模型服务异常仍保留首轮日志与截图入口。取消、超时、版本变化后的迟到结果不会覆盖会话。
- 修复来源保留当时脚本、用例编辑版本和变量快照；同名变量仍为套件优先。一次性运行变量需重新输入，不因缓存丢失或重新打开会话而静默使用其他值。
- 切换会话、关闭面板时，旧的执行详情请求不能回写新会话。候选验证详情使用独立滚动区域。

### 启用步骤

在 backend 的虚拟环境中执行：

```bash
python manage.py migrate web_testing
```

随后重启后端和 Celery。前端开发模式刷新即可；静态部署需要重新构建发布。旧失败记录没有本次新增的完整快照，需先重新运行用例/套件，再从新失败记录使用 AI 修复。

本次没有访问真实模型、MCP 或被测业务网站，实际模型修复质量仍待测试环境验收。取消可阻止后续步骤及会话回写，但底层同步 Python 执行器已启动时会受其运行超时约束，不能保证瞬间终止，更不会撤销已经发生的网站操作。

### 人工确认保存修正（2026-09-06）

修复“候选待审核但保存按钮永久置灰”的流程问题：仅有自动修复范围警告时，按钮改为「人工确认并保存」，确认框明确尚未实际验证。原有会话重新获取即可使用，无需重新调用模型或变更数据库结构。自动验证规则不放宽，原失败记录不变，采用后的新脚本仍需用户调试验收。

本轮回归：427 项后端测试、151 项前端测试及构建通过。隔离浏览器使用实际范围检查产生受限候选，已验证旧前端复现按钮禁用、新前端取消确认不保存、确认后保存成功、保留未验证状态和失败历史，且不增加模型调用或执行记录。真实网站和模型未参与本轮测试。
