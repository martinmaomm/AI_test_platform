# WebUI 自动断言与待补充草稿

## 已确认的目标

用户只描述测试目标，平台通过同一 Playwright MCP 会话探索操作和结果，再确定具体断言。无法确认断言时保留可编辑、可保存、可调试的 Python 草稿，不因缺少预期文字中止整个生成任务。本设计调整原 v4 流程中“探索前必须确定所有机器断言”的要求；不为旧生成数据增加兼容分支，不清空用户数据。

## 行为约定

1. 需求整理只要求明确测试对象和目标，不要求用户逐字提供页面提示。尚未确定的断言细节允许延后到探索阶段。
2. 已有用户明确预期必须保留。AI 不能为了通过验证，把实际错误结果改写成预期结果。
3. 探索中基于真实成功的页面观察、稳定定位及本轮输入变量构造断言。无法确认的目标标为待补充，并保留目标和原因；不凭空猜测提示、按钮或定位器。
4. 合法的已确认操作继续编译为脚本。待补充断言使用注释，不生成空 `expect`、语法缺口或假断言。
5. 草稿可保存到用例、修改和执行。待补充断言不属于阻断性质量错误，但无效 Python、无效入口、无效操作证据等仍阻断。
6. 执行真实失败时仍报告失败；流程完成但验证不完整时报告“验证未完成”，不能显示或计入通过。该规则覆盖生成工作区、独立用例和套件。
7. 手工补齐断言并删除对应待补充标记后，以当前脚本重新计算状态。需要同版本、同环境下实际运行通过，才能保存为已验证。

## 跨模块数据约定

待补充项在对应操作附近使用单行标记：

```python
# AITS_PENDING_ASSERTION: {"assertion_id":"A1","criterion":"需要验证的结果","reason":"目前无法确认的原因"}
```

平台统一解析真实 Python 注释，忽略字符串中的类似内容。脚本顶部和编辑界面说明：补充真实断言后删除该项标记。

统一 `analyze_assertion_state(script)` 提供验证完整性、待补充项、确认数量和待补充数量。即使没有待补充标记，没有真实断言的脚本仍不得标为完整验证。编辑后重新计算，不以旧元数据覆盖新脚本。

执行器另记录本次实际成功执行的断言数量；仅源码中存在断言不能证明执行到它。临时运行文件负责计数，保存的用户脚本不被插入计数代码；原断言异常继续正常传播。零实际断言或仍有待补充项，均不能获得“已验证”状态。

生成定稿需要覆盖全部验证目标：每个目标要么有真实断言证据，要么明确待补充。提交无效断言证据不能静默转换成已通过。动作入口、动作顺序和定位依据约束不因断言延后而放宽。

## 展示与判定

- 生成：草稿已生成，N 项断言待补充。
- 调试／执行：操作正常完成且存在缺口时，显示“流程执行完成，验证未完成”；有实际执行错误则优先显示错误。
- 用例／套件：未完成验证不计为通过；套件中的实际失败优先于验证不完整。
- 人工编辑：允许补充断言，不再要求人工草稿与自动编译脚本完全一致；继续检查脚本契约、语法、变量及版本一致性。

## 验收

- 不提供准确页面提示的目标能够进入探索，正常化不再被 literal 原文校验拦截。
- 用户明确预期不被探索结果擅自覆盖；动态断言必须有真实观察支持。
- 部分／全部断言待补充仍生成合法草稿，可保存和调试。
- 无效动作、无效定位和实际执行失败不被待补充机制掩盖。
- 仅含注释、字符串中伪造标记、假断言、未执行的断言定义不能造成假通过。
- 手工补充并重跑后能转为通过；修改脚本或环境使旧验证记录失效。
- 单用例、生成调试和套件的状态与统计一致。
- 后端回归、前端单测与构建、Django 检查、迁移检查和差异检查通过。

## 发布边界

实施不调用真实模型、不操作测试网站、不自动重启运行中的任务。若增加状态字段或统计字段迁移，交付时给出迁移及重启说明。浏览器压缩包不进入提交。代码回退不清除已有记录。

新增 `0019_deferred_assertion_execution_state` 迁移仅增加套件的验证未完成计数和执行状态选项，不包含删除或重建用户数据。部署时在后端虚拟环境执行 `python manage.py migrate web_testing`，再重启后端和 Celery。开发模式前端由 Vite 更新；生产部署需重新构建前端。

调度模块目前只有粗粒度的成功／失败状态：包含验证未完成用例时，调度日志不记为成功，并明确说明原因；不捏造失败用例数。真实执行失败仍按原规则触发失败通知。
