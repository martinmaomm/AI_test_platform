# 平台原生执行报告

## 范围

本次将 WebUI、API 与定时任务的报告统一为平台页面，不再依赖 Allure 的 Python 插件、CLI、静态 HTML 或 iframe。
报告读取本次已保存的执行结果，不重新运行测试，也不调用 AI。脚本生成、顺序执行、用例失败后继续执行下一项的策略保持不变。

## 使用方式

- WebUI 执行详情就是报告：查看总体结论、统计、按执行顺序排列的用例、耗时、失败摘要、日志与结束截图。
- 日志和截图按需展开；没有截图应说明缺失，不能把图片加载失败显示成成功。
- 独立 WebUI 报告：`/reports/web/<project_id>/<execution_id>`。
- 独立 API 报告：`/reports/api/<project_id>/<execution_id>`，复用平台已有请求、响应、断言和执行明细。
- 定时任务报告：`/reports/detail/<task_execution_log_id>`，关联本次实际派发的执行记录，再链接到对应报告。
- 报告链接需要登录和对应项目的报告查看权限，不是公开分享链接；通知只发送平台链接。

任务“执行完毕”不等于测试“全部通过”。失败、验证未完成、跳过和未执行均不能记为通过，空任务不能显示 100% 成功。
历史报告应以本次保存的结果和名称等快照为准，不使用后来修改过的套件配置冒充历史结果。

## 实施边界

1. 去掉 WebUI 与 API 执行器的 Allure 参数、装饰器注入、报告生成与返回字段。
2. API 定时任务不得为生成报告再次执行接口；聚合只能消费原执行结果。
3. 去掉前端 Allure 标签、iframe 和旧执行工作目录的静态托管。
4. 删除不再使用的报告字段，以新迁移推进；保留已发布迁移文件以维持迁移链。
5. 保留现有测试用例、执行日志、截图和知识库。旧 Allure 文件、已安装工具以及历史脚本不自动转换或批量删除。
6. 暂不加入 AI 总结、PDF 导出、趋势分析、视频或新的定时调度方式。

## 升级

先停止旧 Celery worker 和后端，备份数据库；在 `backend` 虚拟环境中执行：

```bash
python -m pip install -r requirements.txt
python manage.py migrate
```

从依赖清单删除包不会自动卸载已装包。确认其他项目没有共用此虚拟环境后，可卸载已不需要的插件：

```bash
python -m pip uninstall allure-pytest allure-python-commons
```

本次迁移会移除旧 Allure 路径字段并增加原生报告所需字段；不会删除执行记录、日志或截图。
如果自行编写的旧脚本含 `import allure` 或 `@allure.*`，请删除或改用 Python 日志；不提供伪装的 Allure 兼容模块。
随后重启后端与 Celery。开发前端刷新即可，生产前端需要重新构建发布。

## 验收

- 四个顺序用例中一个失败时，报告应显示 3 通过 / 1 失败，四个结果及各自附件一一对应。
- 源用例重命名或删除后，已保存报告仍可读取，不因空关联导致服务端异常。
- 验证未完成、全跳过、中途异常、加载错误与无权限都应有明确状态；不能使用空数据作为成功兜底。
- 独立链接刷新、登录后回跳、不同项目切换后访问，都应指向 URL 对应的执行。
- API 定时套件每个用例只执行一次；汇总和通知不触发额外接口请求。
- 不安装 Allure 的环境仍可完成执行、持久化结果和展示报告。

离线检查只使用临时 SQLite、内存队列和模拟执行，禁止连接项目配置的数据库、Redis、模型、通知渠道或被测网站。它不代替用户对真实测试脚本的业务验收。

### 本次验证记录（2026-09-06）

- 后端 WebUI、MCP 配置及报告相关回归：354 项通过；知识库隔离回归：72 项通过。
- 前端单元检查：120 项通过；生产构建通过（仍有现有的大包体积提示）。
- 本机临时 MariaDB 11.4：升级、回退、再次升级通过；原执行记录、日志与截图路径保留，模型与迁移无差异。
- 本机隔离浏览器：WebUI 的 3 通过 / 1 失败汇总、失败截图、只看失败、已删除源用例的报告、API 请求响应明细、定时报告链接、刷新及登录后回跳通过。
- 不安装/导入 Allure 的路径检查通过；API 套件单次执行回归确认每个用例只调用一次执行器。

真实数据库未执行迁移，现有后端/Celery 未重启，未触发真实被测网站、AI 请求或通知。定时报告的真实派发和通知渠道仍需部署后验证。旧定时日志没有新关联快照时，不会从当前套件配置伪造历史结果；新运行才有完整关联报告。

## 回退

代码回退与数据库回退需要配套。删除旧字段的反向迁移只能恢复空字段，不能恢复旧路径内容；需要恢复旧 Allure 报告关联时应使用升级前的数据库备份。
不要直接在已升级数据库上启动旧 worker。原截图和日志文件未清理，因此本次没有历史文件恢复操作。
