# 性能测试：网页探索、业务断言与节点 0.3.0 验收

日期：2026-09-18。对应设计：[网页探索与可重复请求计划](../plans/2026-09-18-performance-browser-discovery.md)。

## 交付结果

已实现并验证以下流程：

`性能项目 → 网页探索 → 选择真实接口样本 → 导入计划草稿 → 编辑请求、变量与断言 → 保存 → 单用户验证 → 正式压测`

- 复用现有 MCP 网络采集引擎，但使用性能项目自己的入口、权限和草稿出口；不创建 API 项目、规范或对话工作区。
- 同方法/路径的接口分组，保留不同参数样本；支持查看响应证据、选择 API origin、错误诊断及符合条件的重试。
- 草稿只在当前项目的页面内存中交接并消费一次，不在 URL 或持久化浏览器存储中携带请求内容。导入警告保留在编辑器中。
- 准备步骤每个虚拟用户执行一次，主步骤顺序循环；支持固定变量、每轮唯一变量、Cookie 会话、响应提取、JSON/表单/原始文本请求体。
- 支持状态码、响应字段、严格类型、大小比较、列表长度、包含和存在性断言。请求失败或断言失败不会继续执行本轮依赖步骤。
- 单用户验证使用同一执行模板，必须完成实际请求和全部主步骤才算通过；正式压测要求当前计划、目标、节点具有匹配的成功验证。
- 报告展示请求指标、失败步骤、检查字段、期望/实际值与有界失败样本；一个请求多条断言失败只统计一次失败请求。
- 已发布公开、仅限授权测试的 Agent 0.3.0；网页安装命令使用固定多架构摘要。老节点展示升级提示，不自动升级。

## 用户下一步

1. 刷新网页，在性能项目中打开“网页探索”。选择模型，填写网址、目标及测试操作授权。
2. 探索后选中接口样本和批准的压测目标，导入计划；核对依赖、变量和业务断言。采样不等于完整接口契约，未知登录数据/动态值仍需人工补齐。
3. 在节点安装指导中复制新版镜像摘要。确认没有活动测试后，按 [节点升级说明](../../performance-node/README.md#从-02x-升级) 保留原启动参数与身份卷，手动替换镜像。**不要删除身份卷，也不要同时运行两个同身份节点。**
4. 节点版本显示 0.3.0 后先做“单用户验证”，通过后再根据授权范围启动低负载压测。

## 未验证及范围外

- 没有对 NAS、商城或公网目标发压，也没有在用户的远程节点运行新版真实负载；这些必须在用户升级节点后验收。
- 没有长时间、大并发、跨多节点、真实业务账号池或容量结论。本次本机通过不代表远程网络和目标容量已经验证。
- 本轮不提供任意 Python 压测、CSV 参数池、多 origin 场景、定时压测或 P95 门禁。
- 页面探索可能修改测试数据；取消和失败不能回滚已经发生的业务写入。压测目标的批准方法仍须与计划一致。
