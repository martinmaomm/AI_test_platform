# UI 脚本生成真实验收

日期：2026-09-11。用户授权调用现有“思辰科技 · gpt-5.6-luna”（配置 ID 5），允许操作测试环境数据。只记录脱敏结论，不保存模型密钥或登录凭据。

## 验收口径

- 沿用用户的资源列表完整描述：登录 → 新增并查询验证 → 编辑并查询验证 → 删除并查询验证不存在。
- 通过平台 HTTP 接口提交到真实 Celery，生成后使用平台调试接口连续执行两次，不手工替换业务脚本来制造通过。
- 同版脚本、有效业务断言、日志、截图均须核对；生成结束不等于调试通过。
- 补充一个不同结构的本地页面验证通用性。所有业务场景串行执行。

## 已确认的问题与修复

1. 语义名称被误当成 HTML 属性、下拉框只读状态缺失：补充真实 `html_name`、`readonly` 和命名容器，区分语义近似值与实际 DOM 属性。
2. 缺少实际可执行的定位信息：浏览器构造候选 selector，并用 Playwright 校验唯一性和当前元素身份。不能核对时不提供；不承诺当前结构路径永远稳定。
3. 原生 select 未提供选项：补充实际 value、label、禁用和选中状态，并明确截断边界。
4. 模型在探索时编造固定时间戳：新增平台 `generate_unique_test_value`，真实生成时间值，同轮按变量名复用，脚本在 run 内重新生成。保存时检查已知探索样本是否被固定写入可执行字面量。
5. 确定的局部网址变量被误判为未知：仅解析首个导航前的简单、单次局部字符串赋值/别名，保留未知控制流、重赋值、跨作用域及外域检查。
6. 新增 selector 后观察变长，原压缩先删除全部可见文字：浏览器 JSON、Python 接收校验和模型投影均为控件、文字分别预留预算，并保持当前 surface 顺序。接收校验补充默认字段会增加体积，也须再次验证；大量控件时保留结果提示和默认分类；只保留完整 selector/option value，不切割可执行值。
7. 上游 `page.fill` 会默认修改第一个匹配：受控 MCP 操作入口在浏览器证明多匹配时停止，返回明确定位错误和截图。真实双输入框测试确认阻止后两个值均未改变，唯一定位时仍可正常填写。
8. 模型写代码时遗忘早期成功定位器和二次确认：新增有界操作历史，保留原顺序、成功定位器及输入值，不把工具成功当成业务断言。商城的 21 个成功动作只需 3554 字符，未省略动作；历史截断明确标记，不要求模型重新操作网站。
9. 无 Markdown 围栏的完整 Python 被旧解析器按关键词逐行抽取，丢失赋值、多行参数和括号：改为完整源码/完整代码块提取，不拼接行。实际模型输出 4035 字符且 AST 有效，旧解析结果只剩 1961 字符且语法无效。
10. 新候选被拒绝后沿用旧脚本却显示整理成功：统一返回候选拒绝错误，保留旧稿但进入待检查；后续接受有效候选才清除错误。新增完整草稿、空输出、语法错误、固定样本、超长源码及最终状态回归。
11. 生成完成但调试失败时无法利用现有轨迹整理：增加该状态入口，不重新启动浏览器。已有通过结果、未保存本地修改、版本冲突、正在调试/修复或未处理候选仍受保护。

不增加浏览器/模型调用上限，不引入网站业务词表，不把未知断言自动判为通过，不迁移历史记录。

## 可重复验收工具

从 backend 目录执行：

```bash
.venv/bin/python scripts/verify_webui_generation_live.py --live \
  --generation-id <现有生成记录UUID> --debug-runs 2
```

默认不带 `--live` 时零数据库/HTTP副作用；live 模式使用本机平台接口、短期内存令牌，不生成新任务、不改脚本、不保存用例。报告写到 `backend/temp/live-acceptance/<UUID>/summary.json`。非完整草稿或运行/断言/截图/日志不合格时非零退出。

后端与 Celery 已在队列空闲时重启加载最终代码，前端使用 Vite 开发模式。无需数据库迁移或重装浏览器。ZIP、凭据、临时轨迹与运行截图不纳入 Git 提交。
