- 仍使用原规划调用，不增加模型阶段：规划输出 `shared_constraints`，每个 `description` 完整保留自己的业务目标、局部数据要求、断言和清理要求。

### 当轮新发现 D-03：修改步骤可能只做了同值更新

以下保留首次发现时的现场与未放行决定。后续已经完成修复、实际改名验证及三次独立运行，见 [D-03 后续修复与验收](2026-09-14-api-state-change-fix.md)。

- 子场景 29 中 `unique_name` 和 `updated_name` 都是 `qa_api_live_b_${uuid4}`；系统 `uuid4` 在一次运行内固定，因此两个值相同。
- 执行 81 的真实创建、更新请求正文也证明名称相同。更新接口成功、后续断言同名，不能证明发生了需求要求的改名。
- 本轮新增的验收辅助检查依据**真实请求正文**检查改名前后值；`finish-b-crud` 在保存前主动失败，未写入正式用例，也未为了凑三连跑重复无效更新。
- 该问题与多场景串入不同：新候选已经只有本场景 7 个步骤，且认证和 CRUD 请求成功。后续应通过通用的运行时变量作用域说明、需要改变的状态使用不同值及前后状态验证来修复，不能再做固定网站/字段关键词特判。
- 当前仅补了验收检查和问题记录，**未将 D-03 当作已修复**。页面的“已验证通过”是运行器结果，不等价于本报告的业务验收结论。
