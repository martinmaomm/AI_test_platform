# 多节点并发压测首期实施验收

日期：2026-09-22。依据用户确认的 [实施方案](../plans/2026-09-22-performance-multi-node.md)。本记录区分功能验证、真实进程联动、数据库迁移与尚未完成的容量验收。

## 实现结果

- 正式压测支持固定 1–5 节点，1–1000 总用户、全局启动速率最大 100/s。UUID 排序均分；验证仍一次一个节点。请求配置与运行版本一致的逐节点成功验证才可放行。
- 一条 Run 管整轮，多条 RunNode 冻结参与节点、名称/版本/分配、验证、命令/报告和状态；使用 node_ids 接口及 schema 3 快照。Node→Run→RunNode 与 State→Run→RunNode 锁序保持一致。
- 全部预期身份准入后才开始；成员变化、失联或失败停止整轮，不补位、不重新分配负载。正常收尾先停止新请求、等待在途及最终统计，再回收进程；只有停止确认或完整租约证明后释放全局槽位。
- Master 在统计合并前核对身份、Worker 实例、序号和最终批次；重复不累加、缺号不宣称完整。总体 P95/P99 使用合并直方图；分节点与总体独立保存聚合错误，避免共享对象重复计数。
- 页面支持多选、分配预览、逐节点验证后恢复选择、资格失败阻断、总体/节点切换、资源单位及当前用户未知态。历史节点名称来源明确标记，旧版没有的新证据不补造。
- Agent 0.4.0 / 协议 3 / 快照 3 / Locust 2.43.3。旧 0.3.2 协议 2 客户端仍可管理心跳，明确提示升级，不能领取新执行命令。

## 审查闭环

针对竞态审查补齐：下发命令前的锁内复读、屏障开始前成员再检查、进程退出与最终文件出现竞态、慢爬坡中间分配合法性、停止前终止爬坡任务、在途请求完成后冻结末批、quit 排空后重新判定完整性、错误聚合对象隔离，以及旧记录节点指标中的验证详情权限隔离。

控制器最后命令交付窗口最长 15 秒，命令租约 15 秒、强制退出 5 秒并留 5 秒调度余量，因此没有停止确认时按最后下发后的 40 秒回收边界判定。不是等到原 30 秒预算就无条件开启下一轮。

## 迁移与部署边界

0005 包含删除旧单节点字段，不支持直接逆向迁移。回退必须关闭执行入口、停止新轮次，保留升级后证据，再配套恢复旧代码及升级前数据库备份。临时 MariaDB 的逆向迁移预检已确认阻断，不会任意挑一个成员伪造旧状态。

本机发行和切换结果见后续发布记录。远端节点由用户更新；升级后须重新做单用户验证。真实 2–5 台机器、跨网故障和1000用户容量尚未验收，不据此承诺 RPS、满负载并发或跨机器瞬时同步。
