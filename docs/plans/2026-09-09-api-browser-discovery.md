# API 自动化：从网页探索发现接口的实施计划

- 日期：2026-09-09
- 状态：2026-09-09 用户明确启动实施后，首版已实现；已验证范围与剩余边界见 [验收记录](../api-browser-discovery-acceptance-2026-09-09.md)。
- 已选方案：网页探索 → 平台记录真实接口 → 整理依赖 → 复用现有 API 工作区。
- 原计划阶段仅编写文档；后续用户已明确授权实施与测试。本次完成代码、隔离数据库迁移及真实测试环境验收，未修改当前平台数据库或实际 `.env`。
- 本文保留设计时的风险清单，不将计划条目本身视为测试通过证据；部署与使用以功能指南为准。

## 1. 目标与原则

为没有 Swagger / OpenAPI 文档的项目增加“从网页探索生成”入口。用户描述目标，由 AI 通过 Playwright MCP 操作网站；平台记录真实网络交互，整理出有来源证据的接口与业务顺序，再生成可以脱离浏览器重复运行的 requests 用例。

本功能不是另一套 API 执行器，也不是把已有 UI 脚本生成流程再执行一遍。

1. Swagger 和网页探索是两种接口信息来源，最终进入同一个 API 工作区。
2. AI 负责理解目标、操作页面、建议依赖和断言；程序负责采集、保存、校验和实际执行。
3. 网络记录由程序持续写入，不要求 AI 最后返回一大份完整 JSON 才能保留成果。
4. 抓包结果是观察样本，不是完整接口契约；推断和已观察事实必须区分。
5. 生成、调试、有限修复、采用、保存、导出和报告继续复用现有能力。
6. 保持项目当前的顺序执行方式，不新增并发探索或并发套件策略。
7. 不新增旧数据兼容层，也不借本功能清理已有 Swagger、用例、执行记录或 UI 数据。

## 3. 第一版范围

### 包含

- 一个测试目标对应一次独立探索会话，使用一个明确选择的启用模型。
- 从打开页面前开始监听，同一会话内记录登录及普通增删改查涉及的 HTTP(S) 交互。
- JSON、查询参数、普通 URL 编码表单；保留实际方法、Content-Type 和数据类型。
- 请求顺序、页面/操作线索、请求和响应样本、失败原因、缺失及截断标记。
- Token / Cookie 会话和业务对象 ID 等有证据的依赖整理。
- 接口结果预览、选择范围、交接现有 API 工作区、实际验证与有限修复。
- 正式用例、套件、报告和 Python 导出继续复用现有链路。

### 暂不承诺

- 自动发现全站全部接口、所有角色权限、所有参数组合和隐藏业务规则。
- GraphQL 操作语义、WebSocket、SSE、文件上传下载、二进制协议的自动用例生成。
- 验证码绕过、复杂 SSO、设备绑定、动态签名和前端加密协议的自动适配。
- 用户浏览器远程接管、人工录制器、HAR 导入或导出 Swagger；这些可另行安排。
- 为保证通过而使用探索留下的浏览器登录态、旧 Token 或已有业务数据。

第一版生成用例限于**一个确认的 API origin（协议、主机、端口）**，前端网址可以与该 API origin 不同。多个后端 origin 的请求不能混入同一规范或绕过当前目标校验；应明确列出未纳入部分。跨 origin 登录依赖暂不能自动闭合时，保留证据并提示限制，不假装已完成。

## 4. 用户流程与页面

### 4.1 入口与输入

在 API 工作区提供“从接口文档生成”和“从网页探索生成”两个入口，保持当前 Swagger 入口行为不变。不新增独立的执行中心。

网页入口包含：

- 完整目标网址、测试描述和启用模型；描述中可按需提供测试登录信息。
- 允许探索的业务范围、允许修改测试数据的确认，以及采集/API 目标范围。
- 探索总时限，默认读取配置；不与单次模型请求超时混为一项。

允许修改数据的确认在任务开始前统一完成，不要求每个普通测试动作反复确认。默认只在用户授权的测试范围内操作，不扩大到支付、外部发送或其他未要求业务。

前端和 API 域名不同很常见：开始前允许填写业务 API origin；尚未知时可先发现候选地址，未确认来源仅保留必要的地址/方法元信息，不自动读取或外发正文。需要补采登录等交互时明确安排一次新探索，不能宣称之前未采集的正文仍可恢复。

### 4.2 探索与进度

开始后展示当前业务动作、发现的接口数、记录的请求数、耗时、预算和最近错误，提供取消操作。

一个 AI 智能体顺序完成本轮页面探索；浏览器网络事件由程序监听。浏览器自身可能同时发出多个请求，采集器要正确关联，不能把“业务任务串行”误解为“页面网络请求不可能并发”。

无需 AI 提交 UI Python 草稿或最终页面 JSON 才允许结束。AI 结束或预算耗尽后，由程序整理已经保存的证据。

### 4.3 结果与交接

完成后展示：

1. 本轮实际探索的业务步骤及未完成部分。
2. 发现的接口：方法、地址、所属操作、响应状态和样本数量。
3. 请求/响应示例、可能的登录及数据依赖、待确认信息。
4. 已排除、无法采集或暂不支持的请求及原因。
5. “生成 API 场景”入口，沿用现有真实请求确认机制。

超过当前 50 个端点的工作区范围限制时，让用户缩小范围，不静默丢掉接口；关联登录和数据准备接口也要纳入所选范围。

查看结果和保存接口资料不触发被测请求。用户确认生成和验证后，才进入已有顺序生成、实际执行和有限修复流程；保存正式用例仍是独立动作。

## 5. 网络采集设计

### 5.1 同一会话、提前监听

- 采集器必须运行在控制 MCP 浏览器的 Node 侧，在目标页面首次导航前接入 BrowserContext。
- 覆盖同一上下文的新页面、弹窗和导航，确保登录请求不因监听太晚丢失。
- 不另开一个 Python 浏览器“旁观”，不靠页面内替换 `fetch` 作为唯一采集方式。
- 使用网络事件读取请求、响应和完成/失败状态，不为取得响应正文重新请求接口，也不通过修改响应完成采集。
- 分配独立请求 ID，正确配对重定向、并行请求及重复地址；响应正文应在可读取时完成读取。
- Service Worker、缓存、页面关闭等导致信息不完整时，明确记录缺失；不在首版静默改变网站缓存或 Service Worker 行为。

适配器优先以项目内模块对固定 MCP 包做任务级接入，自动检测所需能力；禁止修改全局 npm 缓存或运行时下载并替换包版本。若现有包没有稳定的接入点，先报告第一阶段结论，再确定受控扩展方案，不直接更换全平台 MCP 实现。

### 5.2 最小记录内容

每条交互保存以下信息，具体模型/字段名在实施时按现有约定确定：

- 采集任务、请求 ID、顺序、时间、页面/导航标识、重定向关联。
- 方法、原始 URL、origin、路径、查询参数、资源类型、Content-Type。
- 必要请求头、请求体，以及实际响应状态、必要响应头、响应体。
- 操作关联线索和关联置信状态；一个操作可以对应多条请求。
- 正文是否缺失/截断、读取错误、网络失败、排除原因及存储引用。

列表归并与原始序列分开保存。相同接口在新增前后各查询一次是两个真实动作，不得在生成时只留一个。

后台轮询、预加载和同一时间发生的其他请求不能仅凭时间接近就断定由某按钮触发。无法确认时保留“关联待确认”，允许用户调整分组。

### 5.3 存储、过滤与边界

- 每个任务独立目录/记录，关联项目和发起者，通过鉴权接口读取；不写到用户主目录或 Downloads。
- 默认过滤静态资源及明显无关流量；分类按资源类型、Content-Type 和授权范围，不绑定某个网站的按钮词或接口名称。
- 未知类型和不支持的流量可保留必要元信息，但不得混入可执行用例。
- 请求数、单条正文、任务总存储量和正文读取等待均设硬边界；超出后保留原因，不能显示“完整采集成功”。具体默认值在第一阶段用样本测量后确定并记录。
- 凭据和 Cookie 不能作为普通摘要发送到所有页面或提供商；模型只接收生成所需内容。原始证据与展示内容分别控制访问，不承诺历史日志已全部脱敏。
- 页面文本、接口响应中的指令都只作为被测数据，不得改变智能体任务或扩大采集/执行范围。

## 6. 从观察样本到可复用 API 用例

### 6.1 接口资产适配

首版复用 `APISpecification` / `APIEndpoint`，增加明确的 `browser_capture` 来源类型及必要来源关联，不增加另一套平行接口库。新增名称均为计划字段，不代表当前代码已存在。

程序将选定且可读取的交互转换为来源快照，保留原始样本引用；规范名称显示“网页探索发现”，不存在上传文件也能正常查看。相关页面不能再假设所有规范都有原始 Swagger 文件。

每个来源快照对应一个 API origin，避免当前 `spec + path + method` 唯一约束误合并不同服务器。生成任务冻结来源版本；重新探索形成新记录，不把旧验证结果套在后来变化的接口样本上。

采集结果交接使用任务、来源版本和选定范围的幂等标识，重复点击不重复创建同一来源或工作区。原始大正文按保留策略清理后应显示“证据已清理”，不能伪造历史样本；删除采集任务不得级联删除已保存的正式用例和执行报告。

结构中明确区分：

- **已观察**：实际请求方法、参数值、Content-Type、响应形状和状态。
- **推断建议**：参数类型泛化、路径参数、变量关系、业务名称。
- **未知**：必填性、取值边界、全部枚举、权限规则、其他响应分支。

只出现一次的字段不能自动标为必填；数字路径片段不能无依据全部改成 ID 参数。推断失败时保留精确样本或待确认项，不伪造接口契约。类型和参数语义不确定时，不自动生成声称全面覆盖的边界/负向测试。

未知必填性、完整 Schema 等不应成为整条流程的强制阻断条件：可以基于足够的真实样本生成正向草稿；只有缺失信息会影响合法请求构造、目标身份、鉴权或真实结果判断时，才针对具体步骤提示处理。不要求用户补写 DOM 定位器或一整份接口规范。

### 6.2 依赖与动态数据

- 结合请求先后、响应值与后续输入匹配、页面操作和业务目标提出依赖；相同字符串并不自动证明依赖关系。
- 登录接口不能因为后续调用带 Token，就被错误配置成登录前也要求 Token。
- 用例运行时重新登录提取 Token，或通过 requests Session 接收 Cookie；禁止默认复用探索时的会话快照作为长期认证。
- 新增后从响应或唯一查询提取对象 ID，后续修改/删除只操作本轮创建的数据；继续复用当前唯一条件提取和匹配数量检查。
- 仅将需要唯一性的业务输入替换为 `timestamp_ns`、`uuid4` 或配置变量，不把所有数字、时间和字符串都参数化。
- 保持每个场景独立，不能让场景二依赖场景一或探索会话已创建的对象。
- 签名、加密、验证码或跨 origin 鉴权无法重建时，提示“无法独立请求验证”并保留原因，不将旧 Token 写死来冒充可复用。

### 6.3 断言与验证

- 根据测试目标和样本建议断言，优先验证业务结果以及新增/编辑/删除后的状态，而非只有 HTTP 200。
- 样本响应不是正确答案模板；动态时间、ID、Token、列表顺序不能整包固定为预期。
- 删除后查不到数据必须有有效查询范围或分页依据，不能拿第一页没有目标就断言删除成功。
- 不明确的预期展示待确认信息，不能通过删掉断言或把失败实际值复制成预期来伪造通过。
- 复用现有每场景最多 3 轮候选尝试、失败证据、人工处理和采用/保存机制；不新增无限自动重试。
- 请求超时、远端是否生效未知、权限错误或服务端错误时，保持现有谨慎重放策略。
- 最终验收必须使用全新 requests Session 和本轮新数据，独立重跑至少两次；平台运行和导出的 Python 行为一致。

## 7. 生命周期、取消与失败恢复

采集任务状态与用例验证状态分开，建议采集状态为 `queued / running / finalizing / completed / partial / failed / cancelled`，并另外记录当前阶段和采集完整性。这些是待实施设计值。

- `completed`：采集流程正常结束，不代表已探索完整业务，也不代表 API 测试通过。
- `partial`：预算、正文缺失、采集异常等导致证据不全，但有可查看结果；仅完整且足够的选中证据可交接工作区。
- `failed`：无法启动会话、采集能力缺失或无可用成果；返回具体原因，不显示空列表成功。
- `cancelled`：停止继续操作和生成，有限等待已收到响应的保存，释放本任务浏览器进程；取消不撤销远端已生效的业务操作。

轮询、刷新或断开 WebSocket 不应丢失已保存结果。通过任务标识和版本阻止旧结果覆盖新请求；队列重复投递不能重复执行探索写操作。

浏览器中断后可以整理已有证据，但不能声称无缝恢复原浏览器会话。需要继续探索时创建新任务并明确说明可能再次操作网站。退出与异常清理只释放本任务资源，不终止其他 UI/API 任务或清空队列。

沿用单 worker 的顺序任务部署。探索总时限、单次模型超时、MCP 工具预算和后续 API 验证总时限分别说明；不因新增采集而全局抬高现有 UI 限制。

## 8. 分阶段实施与验收关卡

所有阶段当前均未开始；第一阶段通过后才进入接入业务数据的阶段。

| 阶段 | 交付物 | 验收后才继续的条件 |
| --- | --- | --- |
| 1. 采集技术验证 | 项目内、默认关闭的 MCP 网络采集适配器和本地合成测试网站 | 首次导航、登录、新页面和普通 CRUD 请求/响应可正确配对；采集不额外发请求、不改变页面行为；证明固定包接入可维护 |
| 2. 采集任务与证据 | 任务模型、记录/正文存储、项目权限、状态、取消、资源限制及增量迁移 | 刷新可恢复、异常有证据、重复消息不重复写、跨用户/项目拒绝访问；独立临时数据库迁移通过 |
| 3. 接口资产与依赖 | 网页来源适配、样本预览、来源版本、接口选择和依赖建议 | 不制造必填等未知规则；不合并不同 origin；保留必要重复请求和认证依赖；能接入当前范围校验 |
| 4. 工作区生成接入 | 采集来源上下文进入已有生成、验证、修复和导出链路 | 不改 requests 契约；全新 Session 和数据可重复运行；候选不能自动覆盖正式用例 |
| 5. 前端完整流程 | 两种来源入口、输入/确认、实时状态、结果预览和交接 | 浏览器实测生成与取消、刷新恢复、部分失败、无数据、权限错误和返回工作区；显示观察事实与推断区别 |
| 6. 回归与真实验收 | 测试报告、部署说明、功能开关和中文提交 | Swagger、UI 生成、API 套件和导出回归；经用户明确启动实施并授权目标后再做真实网站与模型验证 |

阶段之间可分别提交，但未完成的入口保持关闭。每次只做当前阶段必要改动，不顺带重构 UI 生成器、知识库或通知系统。

## 9. 必测场景

以下保留原设计核对项；各项测试层级、实际执行结果及未覆盖边界见 [验收记录](../api-browser-discovery-acceptance-2026-09-09.md)，不代表对所有网站与模型的质量保证。

- [ ] 先监听后导航，登录请求与响应均记录；Token / Cookie 来源可追溯。
- [ ] 页面和 API 位于不同 origin；未知第三方正文不进入采集或模型上下文。
- [ ] 一个按钮触发多请求、后台轮询、相同 URL 多次调用及重定向不会配错或丢步骤。
- [ ] JSON、表单、空响应、业务错误响应和网络失败能正确区分；读取失败不是空 JSON。
- [ ] 超量、截断、长连接、页面关闭和缓存等不完整情况有明确结果，不能伪装完整样本。
- [ ] 新增 → 提取本轮 ID → 编辑 → 查询验证 → 删除 → 查询验证的依赖完整。
- [ ] 关闭探索浏览器后，以全新请求会话和新数据连续运行两次，不借用旧 Token / ID。
- [ ] 零匹配、多匹配、未知签名或鉴权不能重建时明确停下，不修改已有业务对象。
- [ ] 不因为样本恰好成功，就推断必填、枚举、固定列表数量或全部权限规则。
- [ ] 当前候选修改后旧验证证据失效；采用、保存和独立运行仍是不同动作。
- [ ] 任务取消、进程异常、重复投递、刷新、旧任务回写和跨项目读取有回归覆盖。
- [ ] 已有 Swagger 生成、UI 探索/调试、API 顺序套件、平台报告和 Python 导出无回退。

测试顺序：纯转换单测 → Node 采集与本地合成站点 → 临时数据库/模拟模型集成 → 隔离浏览器页面验收 → 获授权的真实模型与测试站点。

最终记录请求数量、依赖、断言、两次独立执行及导出运行证据；单测/模拟通过不能写成真实网站已通过。不得对生产或未指定系统执行写入。

## 10. 分工、部署与回退

- 主 Agent：计划维护、接口和状态约束、范围控制、代码审查、独立回归与验收。
- Terra：后续跨前后端、采集、数据模型及核心流程实施；仅在用户要求开始后委派，不在本轮提前开发。
- 多 Agent 不同时改相同文件；每阶段列出文件归属。小范围问题定位清楚后再按项目规则决定是否由 Spark 处理。
- 实施时增加独立功能开关，默认关闭，不改变现有 Swagger 入口。环境变量名与实际默认值在实施阶段补入部署说明，不要求用户现在修改 `.env`。
- 数据迁移采用新增来源/字段/表的方式，不删除现有数据，不运行历史清理脚本。部署前评审迁移、备份并停止旧 worker 后再升级。
- Node MCP 浏览器继续与 Python Playwright 分开；不得为新入口无提示升级共用 MCP 包。
- 出现问题先关闭新入口、停止新的采集任务；保留历史证据，旧 API/UI 流程继续可用。代码与 Schema 回退必须配套，不强行逆向删除已有采集数据。
- 真实探索有业务写入时，记录已执行动作及清理结果；回退平台代码不会撤销远端测试数据。
- 阶段完成后使用中文提交信息，浏览器 ZIP、实际 `.env`、原始凭据和测试产物不提交。

## 11. 实施前重新核对

用户准备先处理其他改动，因此本文不绑定后续精确提交号。正式开始时先核对：

1. API 来源模型、工作区状态和 requests 契约是否已有变化。
2. MCP 包、浏览器版本和输出启动器是否仍与本计划一致。
3. 采集 origin、测试目标和数据写入范围是否明确。
4. 第一阶段稳定接入点、采集上限及所需新增文件是否已验证。
5. 真实验收的账号、目标、调用费用和运行权限是否在当次授权范围内。

本计划的启动条件已由 2026-09-09 用户的实施请求满足。计划本身不代表测试通过；具体已验证范围、限制与部署方式见 [功能说明](../api-browser-discovery.md) 及配套验收记录。
