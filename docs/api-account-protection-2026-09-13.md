# API 执行记录与登录账号保护

## 已确认范围

- 工作区调试、AI 自动验证和正式执行共用现有执行记录，不因未关联环境或未保存用例而隐藏。
- 列表按执行记录的项目归属和项目报告权限查询；来源只展示安全的派生标签，不返回输入快照中的凭证。
- 防止角色生命周期测试修改登录账号或其正在使用的共享角色。正常登录、登出、读取资料、普通业务请求不因新策略而停止。
- 不使用固定账号、商城 URL、字段关键词黑名单判断业务语义；不改变 UI 自动化流程。

## 账号保护方式

模型根据接口文档与用户目标，为有关账号/角色的步骤生成 `account_safety` 声明。平台对声明中的请求绑定、成功响应和本轮对象身份做确定性检查。声明是生成契约，不是另一套执行引擎；字段规则和模型提示由同一 requests 运行模块提供。

1. 登录身份及其共享角色进入本轮保护集合；变量被覆盖不能撤销已确认的保护。
2. 角色分配、账号修改/删除等测试优先独立创建临时账号和临时角色。创建接口不返回 ID 时，用本轮唯一标识精确查询，不能把影响行数或旧数据当成新 ID。
3. 发送相关请求之前，从真实请求参数、请求体或路径解析目标，而不是只相信模型在说明里写的目标值。
4. 命中受保护身份时阻止该请求；无法确定来源时要求检查。已确认创建的临时对象可继续测试并清理。
5. 平台自动验证、工作区调试、保存用例、套件及 Python 导出复用同一个运行核心，不在提示词里声称已代替执行检查。

## 避免正常生成被中断

- 普通步骤不新增必填声明；没有账号操作的用例不额外调用模型、不增加生成轮次。
- 草稿整理和保存不因账号策略问题直接抛出格式错误。具体问题显示在有关步骤和轮次中。
- 静态可修复的问题使用原有最多三轮预算，让模型补临时对象和绑定后继续；不增加无上限重试。
- 仍无法确认时标记“需要人工处理”，保留候选、原因和已产生的执行证据，供继续对话或手动编辑。
- 已经发生真实请求后出现账号保护提示，不盲目重新跑整套流程；临时资源的安全清理仍由执行器处理。
- AI 修复不得仅删除已知账号保护声明来通过检查，也不得删除业务目标或弱化断言来伪造通过。

## 边界

这是针对生成误操作的保护，不是任意 API 的安全沙箱。接口业务语义来自文档与模型的显式声明；完全没有声明、被错误分类或被用户主动删去保护的任意脚本，不能宣称平台已识别所有账户操作。旧用例不会自动获得新的业务语义，也不做未经确认的批量数据重写。

因此，不为所有 POST 或所有携带 ID 的请求套账号限制，不因另一类资源恰好使用相同数字 ID 而误拦。后续若要强制覆盖所有第三方站点，需要单独设计可审阅的端点业务分类，而不是追加 URL 词表。

## 验收与回退

- 覆盖无环境/无保存用例的历史记录、来源筛选、详情和跨项目报告权限。
- 覆盖受保护账号和共享角色、临时对象放行、未知身份提示、变量覆盖、清理以及独立 Python 导出。
- 生成回归覆盖普通场景一次完成、静态问题修复后继续、有限重试后保留草稿、运行时拦截不自动重放。
- 不修改被测商城的程序或历史数据；本次不需要数据库 Schema 迁移。
- 回退本次代码提交并重启后端和 Celery 即可回退平台行为；已保存执行证据仍保留，已发生的外部操作不能通过代码回退撤销。

### 本次验收结果（2026-09-13）

- 后端：requests 运行核心及导出回归 71 项（另含 8 个子测试）通过；隔离 SQLite 中生成编排、工作区及执行记录回归 99 项通过。业务请求均为模拟，不接触商城。
- 前端：288 项单元测试和 Vite 构建通过；构建仍有已有的大文件体积提示。
- 使用平台配置的“思辰科技 · gpt-5.6-luna”做一次真实流式生成，约 39 秒产生 6 个带身份保护的步骤；同一候选在原生运行器与导出 Python 中均通过隔离业务模拟并完成清理。未将模拟通过等同于商城全链路通过。
- 重启后的真实 HTTP 和 Chrome 页面只读验收：项目现有 36 条记录可读取（22 条工作区调试、13 条 AI 自动验证、1 条正式执行），来源切换、清空、统计和无保存用例的详情打开均通过；没有新增或删除业务数据。
- 历史记录直接按现有项目归属展示，不需要重新运行或迁移数据库。旧用例没有保护声明时不会被自动重写；新生成的账号/角色场景才由新契约约束。
