# 项目知识库：手工测试用例生成与知识问答设计

- 日期：2026-09-06
- 状态：用户已批准实施；首版代码和本地隔离验收已完成，用户数据库迁移与真实模型质量验收待进行。
- 交付记录：初稿为设计；后续已新增独立知识工作区、资料版本、手工用例和问答任务。使用与验收边界见 [项目知识库指南](../../project-knowledge-guide.md)。
- 首批入口：UI 自动化项目中的“项目知识库”。数据按项目归属设计，暂不改造 API、App 等模块的入口。

## 1. 目标与已确定的边界

项目知识库长期保存需求、业务说明和补充规则，提供两个独立的业务功能：

1. **生成手工测试用例**：结合项目资料整理测试点，生成可编辑、可保存、可导出的人工测试参考。
2. **项目知识问答**：用户针对当前项目提问，回答附带可核对的文档来源；资料不足时明确说明。

文档管理是两项功能的共同基础，不是第三套 AI 工作流。项目化价值包括资料归属、持续维护、跨文档规则关联、用例积累及来源追溯，而不只是文档切片。

必须保持以下边界：

- 不接入、不修改当前 MCP 探索、Python 脚本生成、AI 辅助调试、脚本执行和套件运行流程。
- 手工用例与自动化脚本分开存储、分开展示；不能进入自动化套件，也没有“运行脚本”按钮。
- 两项新功能均不启动浏览器、不调用 Playwright MCP、不操作被测网站。
- 不恢复页面／元素库，不自动把手工用例转换成 Python，不把问答结果自动写回知识库。
- 不改 Allure、定时报告、通知链路，不引入手工测试执行计划或缺陷管理。
- 保留现有 API 场景生成的知识库调用；不全局关闭 RAG，不删除本地向量模型。
- 不为旧的 WebUI 生成记录或旧手工用例设计兼容层。保留无关 API 契约属于范围控制，不代表要兼容已经淘汰的 UI 流程。

## 3. 方案选择

- **单文件临时生成**：实现较轻，但每次重新选资料，难以持续利用项目知识。不是本次目标。
- **项目分片资料库＋独立手工用例生成／问答，采用**：共用文档和索引，各自保留任务与结果。
- **知识库接入自动化探索智能体**：会扩大已经稳定的脚本生成链路，本次明确不做。

分片本身由普通代码完成；语义检索使用向量模型。保留项目现有向量能力，但两项功能不能只靠同一套“取最相似的几段”策略：

| 功能 | 主要读取方式 | 为什么不同 |
| --- | --- | --- |
| 手工用例生成 | 枚举用户选定章节，按顺序整理测试点；检索补充其他资料中的关联规则 | 需要交代选定需求的处理覆盖，不能把未检索到的章节当成不存在 |
| 项目知识问答 | 根据当前问题检索相关片段，补充邻近上下文 | 需要针对问题作答，不要求每次阅读整个项目 |

## 4. 页面与用户流程

### 4.1 项目知识库工作区

保留当前项目选择器，工作区提供三个页签：

- **项目资料**：上传、分类、处理状态、正文／来源预览、启用或停用、更新和删除。
- **手工测试用例**：生成入口、生成记录、已保存用例、编辑及导出。
- **知识问答**：输入问题、参考范围、回答与来源、本人会话历史。

未选择项目时不能上传或生成。切换项目后切换文档、用例和会话范围，不能把上一项目的选中文件或聊天上下文带到新项目。

页面主要使用“正在解析”“正在建立检索索引”“可用于问答”等用户能理解的状态；分片数、模型和向量存储信息放在技术详情，不要求用户理解 RAG 才能使用。

### 4.2 项目资料

1. 上传文件，填写文档类型；业务模块为可选纯分类，未填写归入“未分类”。
2. 文档类型先提供“需求文档、业务规则、操作说明、其他”，不维护特定网站的业务词表。
3. 用户点击“处理文档”后，后台顺序完成解析、结构化分片及索引建立。
4. 展示解析状态与索引状态，失败分别提示原因，支持重试失败阶段。
5. 用户预览解析后的章节和原文位置，发现解析质量不合格可换文件重新上传。
6. 可以替换文件形成新内容版本，或停用旧资料；不依据上传时间自动认定某份文档更权威。

首版可靠解析格式为 TXT、Markdown、DOCX、可提取文字的 PDF、XLSX。旧 DOC／XLS 在新入口明确提示转换，不生成“解析成功”的说明文字代替原文。扫描 PDF、图片内容及复杂排版解析不完整时标为需要处理；首版不增加 OCR 或视觉模型依赖。

### 4.3 手工测试用例生成

1. 在当前项目输入目标范围，例如“用户管理的新增、编辑及权限校验”。
2. 选择作为主需求的文档和章节，可以同时选择多份；补充资料默认取当前项目启用且索引就绪的资料，也可缩小范围。
3. 若从整个项目开始，先展示候选文档／章节清单，让用户确认本次主需求范围。模型建议相关章节，不自动宣称已选中全部需求。
4. 选择模型，显示模型名称和提供商；提交前展示本次包含及未包含的资料。
5. 后台按章节顺序整理测试点，检索关联规则，生成用例并合并重复项，持续保存已完成批次。
6. 用户查看用例草稿、来源、范围处理情况及待确认问题，编辑后选择保存全部或部分。
7. 保存到当前项目的独立手工用例列表，支持导出 XLSX。首版不再叠加多种导出格式。

新生成的结果先是任务草稿；点击保存才进入正式手工用例列表。重复点击保存不能产生重复用例。保存成功清空本次待保存选择，历史生成记录仍可查；后续生成不得自动覆盖用户已经编辑的用例。

### 4.4 项目知识问答

1. 默认查询当前项目所有启用、索引就绪的资料，可限定文档／模块。
2. 用户提问，例如“角色停用后，已有登录状态是否还有效？”
3. 后台先检索，再组织回答；最终回答展示结论、资料依据、存在的限制和来源片段。
4. 点击引用可查看真实文件、章节或页码以及对应原文。
5. 支持同一项目内的连续追问、新建会话和本人会话历史；首版不增加共享会话或公开链接。

知识问答只针对项目资料回答，不联网搜索、不访问文档中提到的网址。没有找到依据时提示“当前项目资料中未找到依据”，给出可以补充哪类文档的建议；不把模型通用知识包装成该项目的规定。

例：资料没有规定密码长度，应说明未找到规定，而不是自行回答“必须 8–16 位”。如果两份启用资料分别写了 8 位和 12 位，应并列引用并提示冲突，不能静默选择一条。

## 5. 共用资料、分片与检索约定

### 5.1 来源必须可追溯

每份处理后的内容版本具有不可变的 revision 和内容 hash。分片至少记录：

- 项目 ID、文档 ID、内容版本 ID、稳定的分片 ID、顺序号。
- 文档标题、类型、模块分类、正文内容、章节层级。
- 原文位置：PDF 页码，表格的工作表及行范围，或文本／Word 的章节、段落及字符范围。
- 是否属于当前可检索版本、处理状态。

没有可靠页码的文件就显示章节／段落，不编造页码。分片优先保留完整标题、规则和表格行，过长才继续拆分，并可附带相邻上下文。

保留可按文档／章节顺序枚举的分片记录，不能仅把分片藏在向量库中。完整处理选定章节时从这些记录读取；向量索引用于找相关内容，不作为唯一正文来源。

### 5.2 两阶段就绪状态

- **解析就绪**：正文与章节可预览，可作为手工用例的主需求材料。
- **索引就绪**：当前版本已成功建立索引，可参与语义检索、关联规则补充及知识问答。
- 解析失败不得进入两条 AI 流程。索引失败不能抹掉已经成功解析的正文。
- 主需求解析就绪但索引未就绪时，允许用户明确选择“仅基于所选正文生成”；展示未使用哪些补充资料，不假装完成跨文档检索。
- 问答所选资料尚未索引完成时，先列出不可用范围，由用户选择等待或明确排除。全部不可用时不调用聊天模型生成答案。

### 5.3 检索与引用校验

- 后端先取得调用者有权访问的当前项目资料集合，再以项目／文档／内容版本限制检索。
- 检索失败或过滤条件异常时停止，不允许退化成无项目过滤的全库搜索。
- 向量返回结果再次与数据库中的可访问、启用、有效版本核对；不能只信任客户端或向量元数据。
- 排序时结合关键词／标题匹配和语义相似度；去重并在输入预算内补充同章节相邻片段。首版不引入额外重排序模型。
- 提供给模型的每个片段有平台分配的引用 ID；输出只能引用本次提供的 ID。前端文件名和跳转位置由后端解析，不使用模型编造的链接。
- 引用 ID 有效只证明来源存在，不证明语义必然正确。手工用例保留人工审核状态；问答允许打开原文核对，不标注未经实证的准确率。

### 5.4 更新、停用和删除

- 替换内容时原文件不被就地覆盖，新建内容版本。切换当前版本后旧索引立即失去检索资格，新版本未就绪时展示处理中，不暗中查询旧资料。
- 新建向量 ID 由内容版本和分片 ID 确定；任务重试采用幂等写入，不能重复添加相同片段。
- 停用或删除先在数据库中使资料不可检索，再后台清理对应向量；清理失败可重试，仍不得被新查询命中。
- 旧用例／问答保留生成时的引用版本和必要片段快照，显示“来源已更新／已删除”；不自动重写已经保存的结果。
- 文档删除确认必须说明历史结果中的引用快照仍会保留。若需要彻底移除这些内容，另行明确操作范围；本次不实现全量隐私擦除工作流。
- 正在运行的任务固定本次资料版本，不在中途混入新版。后续阶段发现所选资料更新、停用或删除时，停止继续读取，保留已有内容为 `partial` 并提示重新选择资料发起任务；已完成结果标记“基于旧版本”。权限撤销则停止后续读取与输出，历史快照也不得绕过当前项目权限。

## 6. 手工用例的生成质量与结果契约

### 6.1 生成方式

生成阶段为：确认资料范围 → 顺序整理测试点 → 补充关联规则 → 分批生成用例 → 检查重复与缺项 → 展示草稿。

每个章节保存已处理状态及对应测试点 ID。最终展示“选定章节数、已处理、明确排除、待处理”，并关联测试点和用例；这是**资料处理覆盖**，不是模型保证的需求完整率或测试通过率。

正常、异常、边界和权限类测试点按文档内容分析，不强制给所有业务套同样的固定模板。对于需要推导的测试建议，明确标为“建议补充”，不能声称原文已有规定。

### 6.2 单条用例字段

- 标题、业务模块、测试类型（正常／异常／边界等）。
- 前置条件、测试数据、编号步骤及逐步对应的预期结果。
- 来源引用、关联测试点、待确认问题。
- 审核状态：未审核／已审核；待确认项另行保留，不等于审核通过。

首版不增加执行状态、执行人、缺陷编号、优先级管理或自动化脚本字段。没有文档依据的预期结果应写明待确认的具体规则，而不是填写确定但虚构的值。

### 6.3 部分结果和格式错误

- 每批输出做结构校验；缺失的非核心信息作为待确认项，不能因为一条用例有问题丢弃全部结果。
- 当前批次格式损坏时允许一次限定格式修复，不重新发起已成功批次；仍失败则保留可读草稿并提示人工处理，不能伪装成已保存的结构化用例。
- 超时、取消或提供商故障保留已完成草稿及剩余章节。首版支持编辑、保存有效部分，未处理范围由用户新建任务继续，不做复杂自动续跑智能体。
- 导出包含来源和待确认项；对以公式触发字符开头的单元格按纯文本写入，不能把生成内容当成可执行电子表格公式。

## 7. 问答上下文与结果契约

- 会话绑定项目和创建用户，不把其他用户的私人会话用作检索材料。
- 每轮冻结实际参考的资料版本，并重新验证权限、启用状态和所选范围。
- 历史问题可帮助理解追问；旧回答本身不是业务事实依据。资料更新后重新检索，不能继续把历史模型答案当成有效文档。
- 上下文过长时只保留预算允许的近期轮次，并提示用户；原始会话记录仍可查看。首版不引入长期记忆或自动摘要记忆系统。
- 回答包含正文、引用列表，以及足够依据／依据不足／资料冲突等结果类型；部分问题有依据时分别说明，不一概成功或失败。
- 流式正文显示为“生成中，引用待核对”；完成引用校验后才转为正式回答。流中断时保留为“未完成回答”，不能显示已确认结论。
- 取消、资料不足和冲突属于明确的业务状态，不作为系统崩溃报错。
- 用户上传文档中的指令只作为资料内容，不得改变系统约束、扩大项目范围或触发工具调用。

## 8. 实现边界与数据划分

建议新增独立后端模块 `backend/apps/project_knowledge/`，承载项目知识应用，复用公共上传资产、项目权限和模型配置。不要往 WebUI 脚本智能体中增加分支。

主要数据分为以下几类，实施时可按职责合理合并表，不在本阶段绑定完整 SQL：

| 数据 | 最小职责 |
| --- | --- |
| 文档应用元数据 | 关联现有知识库文件、文档类型、模块标签、启用状态、当前内容版本 |
| 内容版本与分片 | 原文结构、内容 hash、处理状态、稳定引用和可枚举片段 |
| 知识任务 | 类型、用户、项目、资料快照、模型、状态、阶段、已完成批次、错误及草稿 |
| 手工测试用例 | 人工可读用例字段、审核状态、编辑 revision、来源及生成任务 |
| 问答会话与消息 | 用户与项目、问题、回答、状态、来源及任务关联 |

知识库的“模块”首版采用项目内的文本分类标签，不依赖 `WebUITestModule`，不因分类而重新引入脚本或页面元素模型。文档和用例标签支持从现有值选择，也可填写新值，默认“未分类”。

新索引使用独立 collection／namespace，复用现有嵌入模型配置，不重建或清空现有 API 索引。新服务为自己的内容版本、分片与索引负责；原 API 处理任务不自动双写新索引。

当前文件首次在新功能使用时需显式重新处理，创建可追溯的来源分片。不推断旧向量的章节、页码或版本。文档只设计这一步骤，不授权现在执行清库或批量重处理。

前端新增 `frontend/src/views/project-knowledge/` 工作区及独立 API 文件；仅切换 UI 项目的知识库路由，其他项目类型的共用旧页面先保持原状。

### 8.1 接口边界草案

新接口均以 `/api/v1/projects/{project_id}/knowledge/` 为作用域，沿用项目现有 JSON 响应封装；原 `/knowledge-base/` 文件接口不做不兼容替换。

- `documents/`、`documents/{id}/`：资料清单、应用元数据及详情；上传复用公共文件服务。
- `documents/{id}/prepare/`：启动解析／索引任务，支持指定失败阶段重试。
- `documents/{id}/sections/`：可选择章节与就绪范围。
- `case-generations/`：提交主需求范围、补充资料范围、生成目标、模型配置及客户端请求 ID。
- `tasks/{id}/`、`tasks/{id}/cancel/`：任务状态与取消；请求 ID 防重复提交。
- `case-generations/{id}/save/`：保存选中草稿项，按任务与草稿项 ID 幂等。
- `manual-cases/`、`manual-cases/{id}/`、`manual-cases/export/`：用例查询、编辑与导出；编辑校验 revision，避免覆盖已改内容。
- `conversations/`、`conversations/{id}/messages/`：会话与提问；每次提问返回任务 ID。
- `sources/{chunk_id}/`：查看有权限的来源片段，不提供无鉴权的文件或向量访问入口。

生成／提问／处理任务返回 HTTP 202 和任务 ID，不让浏览器 HTTP 请求一直等待模型完成。模型提供商和使用模型的标识由服务端配置解析并记录，不能信任客户端传来的名称。

## 9. 任务、流式与资源管理

- 两项功能均复用流式 Chat API。新入口预检所选模型适配器具备流式接口，不具备时明确提示，不改变共用模型管理器的其他调用方。知识库任务自身不在流失败后偷偷转非流式重放；有异常就进入有限重试或明确终态。
- 文档、章节、生成批次和模型调用顺序执行，不并发扇出，不改现有自动化套件的顺序语义。
- 文档选择阶段展示处理规模；超过模型输入预算按章节分批，绝不无提示截断后声称已读全文。
- 请求超时继续使用现有 `AITS_LLM_TIMEOUT_SECONDS` 语义；知识任务新增独立总时限配置，建议默认 1200 秒、首版允许上限 1500 秒，低于当前 Celery 1800 秒硬上限并留出保存时间。实施时再次核对有效 Celery 配置。
- 总时限从 worker 开始处理该任务时计时，不包含队列等待；单次请求受“请求时限”和“任务剩余时限”共同约束。流式不代表可以取消绝对总时限。
- 短暂 429／5xx／网络故障只在剩余预算内最多额外尝试两次，尊重服务商返回的等待要求。鉴权、参数、资料缺失、权限、模型上下文超限不盲目重试。
- 已经产生部分输出的批次不能直接拼接重试结果。标记该次尝试未完成，最多在预算内重做当前批次；已完成批次不重跑、不重复保存。
- 任务状态至少有 `queued / running / completed / partial / failed / cancelled`，另存当前阶段和可读提示；资料不足／冲突记录为结果类型而非假装基础设施故障。
- 页面能显示排队、当前章节／批次、已完成数量、最后更新时间。状态持久化到数据库，刷新能恢复；初版使用任务轮询读取累计输出，无需重做全站 WebSocket 协议。
- 取消是协作式的：立即记录取消意图，阶段间检查；正在进行的网络调用不承诺瞬间退出。迟到结果不得覆盖取消后的终态。
- 超时或 worker 意外退出后，过期任务应转为明确终态并保留已持久化部分，不能无限显示“生成中”。
- 业务隔离不等于资源隔离。共用串行 Celery 时新任务会占用队列；首版明确显示排队，不承诺问答一定即时返回。不以全局提高并发解决；独立 worker／队列留作后续部署选择。

## 10. 权限与外部数据边界

- 项目创建者／负责人具备管理权限；普通成员沿用项目现有查看和编辑能力，并在新服务统一校验，避免不同入口对创建者处理不一致。
- 查看资料／用例和使用问答需要项目查看权限；上传、更新、停用、删除资料，以及生成／保存／编辑手工用例需要编辑权限。
- 任务、会话历史默认只对发起者可见，正式手工用例按项目权限共享。首版不增加管理员跨用户会话审阅功能。
- 所有文件 ID、任务 ID、分片 ID、用例 ID、会话 ID 都要与路径项目和当前用户权限重新核对；轮询、引用预览与导出也不能例外。
- 前端提示：所选文档内容或相关片段将发送给所选模型提供商。只发送本次必要资料，不把整个项目或全部会话无条件拼入请求。
- 不增加与本需求无关的全局日志脱敏改造，沿用项目现有策略；任务日志以 ID、阶段、范围和错误为主，不额外采集 API 密钥。
- 数据库迁移采用新增结构，不删除现有脚本、执行记录、API 资料或模型缓存。任何后续破坏性数据清理需单独明确目标和授权。

## 11. 分阶段实施与交付

### 第一阶段：项目资料与检索底座

- 新模块、资料元数据、内容版本、结构化分片、独立索引及权限过滤。
- 分开解析／索引状态，支持引用预览、文档有效性和失败重试。
- 替换 UI 项目的资料页入口，验证原 API 知识库和自动化入口不受影响。
- 交付门槛：两项目同名文档不串数据；更新、停用、删除后检索正确；解析失败可定位。

### 第二阶段：手工测试用例闭环

- 选资料和章节、确认范围、顺序生成、来源和覆盖展示、编辑保存与 XLSX 导出。
- 独立任务与草稿恢复，支持部分完成和幂等保存。
- 交付门槛：从多份相关资料生成可审查用例；中途失败不丢已完成部分；不创建自动化脚本或执行记录。

### 第三阶段：项目知识问答

- 项目内检索、流式回答、来源引用、依据不足／冲突提示、基本多轮会话。
- 验证会话项目边界、资料更新与历史来源提示。
- 交付门槛：能回答有依据的问题，不能凭空回答缺失规则；不会触发浏览器或自动执行。

### 第四阶段：集成验收与部署说明

- 新功能联调、长文档与服务错误测试、迁移及索引准备操作说明。
- 原 API 场景检索和 WebUI 生成／调试／执行回归。
- 每阶段独立中文提交，分别说明已验证与待验证；不把离线测试等同真实模型验收。

首版已按资料底座、后端工作流、前端工作区、集成测试与文档分批交付。没有运行用户数据库迁移，也没有接入原自动化智能体。

实施取舍：范围由用户明确选择主资料和章节，首版未提供“模型自动推荐章节”入口；停用立即从检索排除并保留索引以便重新启用，删除才异步清理向量。两项行为在操作指南中明确说明。

## 12. 验收清单

| 编号 | 场景 | 必须满足的结果 |
| --- | --- | --- |
| K01 | 两项目包含同名文档、相同问题；伪造另一项目的对象 ID | 正文、检索、引用、任务、会话和导出均不越权 |
| K02 | 创建者未显式列入成员表；只读成员访问 | 创建者按管理权限使用；只读成员不能改资料或生成共享用例 |
| K03 | 文本、DOCX、文本 PDF、XLSX 中的章节与表格规则 | 来源能定位原文；不支持格式或扫描件明确提示，不以说明文本伪装解析成功 |
| K04 | 正文解析成功但向量服务失败 | 正文仍可预览；索引失败单独重试；限正文生成需明确范围；问答不假装资料可用 |
| K05 | 文档更新、停用、删除及向量清理失败 | 新任务不命中过期资料；历史引用显示版本状态；重试不重复入库 |
| K06 | 主需求最后一章包含关键规则，语义相似度较低 | 在选定范围内仍被顺序处理；覆盖统计真实，不只依赖 top-k 检索 |
| K07 | 需求、权限说明、通用校验规范三份资料 | 用例能引用关联依据；去重后来源不丢失；冲突和缺失规则明确标注 |
| K08 | 一批用例输出格式错误、任务超时或取消 | 已完成批次可见；错误批次不污染正式用例；不得无限重试或声称全部完成 |
| K09 | 重复提交、重复保存、保存后修改，再次生成 | 不重复建任务／用例；不覆盖用户修改；草稿和正式用例状态区分清楚 |
| K10 | 问答有答案、无答案、部分有答案、资料互相冲突 | 分别给出合适状态与依据；没有来源时不编造项目规定 |
| K11 | 模型输出不存在的引用 ID，或伪造文件链接 | 引用校验阻止正式引用；不显示虚假来源；正文保留为需核对／未完成状态 |
| K12 | 追问过程中资料更新、切换项目、撤销权限 | 新问题重新检索有效资料；不串会话；撤权后不再读取或输出受限资料 |
| K13 | 模型响应超过 60 秒、断流、429／5xx、队列等待 | 使用流式，显示阶段；遵守总预算与有限重试；不把排队显示成完成或假死 |
| K14 | 页面刷新、worker 退出、取消后迟到结果 | 恢复已持久化进度；过期进入终态；迟到结果不改写已取消任务 |
| K15 | 含指令性文字的资料、恶意 Markdown、公式型导出内容 | 资料不能扩大权限或触发工具；前端安全渲染；导出不执行公式 |
| K16 | 原 API 知识库、WebUI 生成／调试／单用例／套件 | 原入口、数据与执行语义不变；新流程不启动 MCP，不产生浏览器操作 |

测试分层：

1. 单元／离线集成测试使用临时数据库、临时向量索引和模型桩，禁止连配置中的 NAS、真实模型及被测网站。
2. 专用临时 MySQL／MariaDB 库验证迁移及唯一性，不只依赖 SQLite；使用临时 collection 验证实际使用向量后端的过滤、幂等和删除行为。
3. 前端验证范围选择、队列和阶段、刷新恢复、来源、部分结果及保存后状态。
4. 真实模型验收使用人工可核对的小型多文档样本，包含缺失规则、冲突规则及低相似度章节；核对实际引用和用例内容，不只看状态为成功。
5. 回归现有 `backend/scripts/test_webui_generation_offline.py`；之后单独进行获授权的现有 UI／API 冒烟，不把离线通过写成线上验证通过。

## 13. 风险、回退与未纳入范围

- 文档解析丢失结构会直接影响答案和用例质量；以可预览来源为前提，不强行声称所有格式可用。
- 向量检索可能漏召回，模型可能遗漏测试点；通过主需求顺序处理、范围展示及人工审核降低风险，不能承诺完全正确或完整覆盖。
- 文档内容版本和历史引用会增加存储，后续再制定保留周期；首版不后台自动删除资料。
- 共享 Celery 和模型服务会产生排队及资源竞争，逻辑分离不承诺性能零影响。
- 先通过功能开关关闭新入口和任务提交即可回退；停止对应新任务，保留新增表和索引以便排查。正常回退不清库、不逆向删除迁移、不重置现有向量库。
- 部署时应用新增迁移、按选择准备新索引并重启相关服务；本次仅在独立临时 MariaDB 验证迁移，用户项目库未执行。不要让已有 Celery worker 继续运行却声称新任务已加载。

明确后置：公开分享、知识问答联网、自动网页采集、自动执行／自动转脚本、OCR、额外重排序模型、复杂版本合并、定时增量生成、手工执行计划、缺陷系统、全量历史数据兼容和全局并发改造。

用户已认可两项功能及其与自动化脚本解耦的总体方向。以上为首版具体设计与验收边界，后续实施以本文件为基线，新增实质范围另行确认。
