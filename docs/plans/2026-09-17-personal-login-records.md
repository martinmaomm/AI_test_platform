# 个人登录记录（方案 A）

用户已确认简化方案：替换首页“进入工作区”，只提供当前用户的成功登录记录，不扩大为全站安全审计。

## 范围与数据流

- 首页与业务工作区的用户菜单统一提供“登录记录”，进入需登录的独立分页页面。
- 平台两个用户名密码登录入口（`/api/v1/users/login/` 与 `/api/v1/auth/token/`）校验通过并签发 JWT 后，新增一条记录：用户、登录时间、IP、最多 512 字符的 User-Agent。保持各自原响应格式；Django Admin 的独立运维 Session 登录不在本次范围。
- 不保存密码、Token、Cookie 或完整请求，不记录失败登录、页面刷新、Token 刷新或校验。历史数据不补录。
- `GET /api/v1/users/login-records/` 只按服务端 `request.user` 查询，管理员也只能看到自己。返回 `data.items` 与 `data.pagination`，默认每页 20 条、最大 100 条，按时间和 ID 倒序。
- 新表与迁移为增量变更，不修改或删除已有用户和测试数据。记录写入失败只记不含请求明文的服务端错误，不阻断已经验证成功的登录。

## IP 可信边界

- ASGI 启动器关闭 Uvicorn 自动转发头解析，保留原始 TCP 对端。
- `LOGIN_RECORD_TRUSTED_PROXIES` 默认只信任 `127.0.0.1/32,::1/128`；其余直连请求忽略 IP 转发头。
- 可信代理的 `X-Forwarded-For` 从右向左检查可信链，遇首个非可信地址即停止；非法或超长链退回 TCP 对端。
- Vite 开发代理主动覆盖浏览器提供的 IP 头，写入其 TCP 对端地址。IPv4/IPv6 均支持；不调用 IP 定位服务。
- NAT 或未正确传递客户端地址的外层代理无法还原真实终端 IP，不凭空推断；代理配置应保持精确、最小信任范围。

## 验收与边界

- 成功登录只新增一条；失败、刷新、续期不增加。记录持久化异常不影响有效登录。
- 未登录不能查询；普通用户、管理员均不可通过参数读取他人记录；接口不可创建、修改、删除记录。
- 验证分页、空状态、失败重试、旧请求覆盖保护，以及直连/可信代理/伪造头/IPv6。
- 执行新迁移、重启后端与 Celery，检查真实 HTTP 链路和用户菜单；Vite 配置变更需重载。
- 第一版不增加地理位置、异常登录告警、管理员全量审计、用户删除记录或定期自动清理。
