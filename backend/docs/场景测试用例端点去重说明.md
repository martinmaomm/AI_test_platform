# 场景测试用例端点去重实施说明

## 📝 优化内容

根据您的建议，我已经在**三个层面**实施了端点去重逻辑，确保场景测试用例的"涉及端点"数据不会重复：

### 1️⃣ 数据提取层去重 (`backend/apps/api_testing/utils.py`)

**位置**: `extract_endpoints_from_test_data()` 函数（第 68-76 行）

**逻辑**: 
- 从测试用例的 `test_data` 或 `request_data` 中提取端点时就进行去重
- 使用 `method + path` 作为唯一键
- 这是**最早的去重时机**，在数据保存到数据库之前就完成

```python
# 去重
unique_endpoints = []
seen = set()
for ep in endpoints:
    key = f"{ep['method']} {ep['path']}"
    if key not in seen:
        seen.add(key)
        unique_endpoints.append(ep)

return unique_endpoints
```

**作用**: 
- 保存到数据库的 `involved_endpoints` 字段本身就是去重后的数据
- 适用于新创建的测试用例和修复脚本处理的旧数据

---

### 2️⃣ API序列化层去重 (`backend/apps/api_testing/serializers.py`)

**位置**: `get_involved_endpoints_with_summary()` 方法（第 77-102 行）

**逻辑**:
- 从数据库读取 `involved_endpoints` 字段后，再次进行去重
- 使用 `method:path` 作为唯一键
- 这是**第二道防线**，确保即使数据库中有重复数据也能过滤

```python
result = []
seen = set()  # 用于去重

for endpoint_data in obj.involved_endpoints:
    method = endpoint_data.get('method', '').upper()
    path = endpoint_data.get('path', '')
    
    # 去重检查：使用 method + path 作为唯一键
    unique_key = f"{method}:{path}"
    if unique_key in seen:
        continue
    seen.add(unique_key)
    
    # ... 查询摘要信息 ...
    result.append({
        'method': method,
        'path': path,
        'summary': api_endpoint.summary if api_endpoint else ''
    })
```

**作用**:
- 返回给前端的 `involved_endpoints_with_summary` 字段是去重后的
- 显示在"涉及端点摘要"列

---

### 3️⃣ 前端展示层去重 (`frontend/src/views/api-testing/ScenarioTestCases.vue`)

**位置**: `getInvolvedEndpoints()` 函数（第 399-415 行）

**逻辑**:
- 接收后端返回的 `involved_endpoints` 数据后，前端再次去重
- 使用 `method:path` 作为唯一键
- 这是**最后一道防线**（双重保险）

```javascript
// 前端去重（双重保险）
const uniqueEndpoints = []
const seen = new Set()

testCase.involved_endpoints.forEach(endpoint => {
  const key = `${endpoint.method}:${endpoint.path}`
  if (!seen.has(key)) {
    seen.add(key)
    uniqueEndpoints.push(endpoint)
  }
})

return uniqueEndpoints
```

**作用**:
- 显示在"涉及端点"列
- 用于过滤器和统计

```json
[

  {"method": "POST", "path": "/user/register"},  // 重复
  {"method": "GET", "path": "/community/list"},
```

```json
[

```

```
│     ↓                                                         │
│  2. extract_endpoints_from_test_data() → 第一次去重         │
│     ↓                                                         │
│  3. 保存到数据库 (involved_endpoints 字段)                  │
│     ↓                                                         │

│     ↓                                                         │

│     ↓                                                         │
│  6. 前端 getInvolvedEndpoints() → 第三次去重（双保险）     │
│     ↓                                                         │

└─────────────────────────────────────────────────────────────┘
```

## 📌 注意事项

1. **旧数据更新**: 
   - 如果有旧的测试用例数据包含重复端点，需要运行修复脚本：
   ```bash
   cd d:\dev\proj\aits-system\backend
   conda activate aits-backend
   python manage.py fix_scenario_fields
   ```

2. **不同方法相同路径不算重复**:
   - `GET /user/profile` 和 `POST /user/profile` 被视为两个不同的端点（这是正确的）

3. **路径变量处理**:
   - `/user/123` 和 `/user/456` 会被视为不同路径（目前未做路径参数归一化）
   - 如果需要将带参数的路径归一化（如都归为 `/user/{id}`），需要额外实现
