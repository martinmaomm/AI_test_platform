# API 生成、验证与有限修复（B 方案）

用户已批准本方案。它接续 `2026-09-06-api-workspace-b.md`，替代其中“生成/修复不自动调试”的旧行为；手动调试、候选采用、正式保存仍保留。

## 目标与范围

一个工作区处理一个顺序执行的场景：选择 Swagger 和范围 → 生成候选 → 文档及结构检查 → requests 试运行 → 最多两轮修复复测 → 用户审阅、采用、保存。

- 保留结构化可视化编排与 Python 单向导出；不在本次重写导出器，不执行模型输出的任意 Python。
- 不实现“覆盖全部接口”的批量场景管理，不引入并行场景或新工具智能体。
- 修复空文档上下文仍生成虚构接口，以及提取失败后丢失 HTTP 响应的问题。
- 生成通过不等于系统没有缺陷；一次运行通过不等于未来运行、其他环境或全部业务都通过。

## 用户操作

1. 明确选择一个 Swagger。只有一份时可默认选择并显示名称；多份时由用户选择。
2. 展示本次端点范围，允许勾选缩小。没有可用文档或端点不能发起生成。一次最多 50 个端点，超过时需缩小范围，不能悄悄截断。
3. 点击“生成并验证”或“修复并验证”，确认目标地址、变量及试运行范围。确认说明会真实请求目标网站，可能新增、修改或删除测试数据；仅使用测试账号。
4. 展示生成、检查、试运行、修复各阶段及当前轮次。每轮保留候选、修改摘要和请求/响应/提取/断言结果。
5. 最终分别显示“已验证通过”“需要人工处理”“生成失败”“验证已过期”。失败草稿仍可检查、采用和手动修改，不强制用户陷入重新生成循环。
6. 候选不会自动覆盖编辑草稿或正式用例。用户先采用，再显式保存为测试用例。

## 后端契约

- 工作区新增 `spec` 可空外键、`generation` JSON 字段；新增非破坏性迁移。
- 创建、修改工作区接受 `spec_id`；限制为当前项目的文档，端点必须属于该文档。
- `POST messages/` 必须携带 `execution_confirmed: true`、明确的 `base_url`、可选 `variables`，以及原有 `message/revision/mode`。同时检查项目编辑与执行权限、本人启用的 LLM。
- 入队时冻结文档、端点、模型、原草稿、目标、变量、revision 和 task id。空 `endpoint_ids` 只能在明确指定文档后展开该文档全部端点，不允许无文档推测。
- 继续使用流式模型调用，requests 运行在原有受控子进程内。Celery 重复投递只能有一个 worker 认领；过期任务或被新任务取代的 worker 不能再次发起执行或覆盖新结果。
- `generation` 的公共状态：`queued/running/passed/needs_review/failed/stale`；阶段：`queued/generating/checking/running/repairing/finished`。
- 公共字段包含 `attempt/max_attempts/source_revision/target_url/started_at/finished_at/summary/rounds/adopted_revision`。内部执行快照和认领标记不对前端返回。
- 每轮包含 `attempt/status/summary/draft/draft_hash/result/changes/started_at/finished_at`；`result` 复用现有 requests 报告契约。

## 验证与修复规则

- 第一轮加最多两轮修复，总共不超过三轮，不能嵌套无限重试。
- 静态检查端点 ID、方法、路径、变量、必填请求项、媒体类型和断言；只有存在实际断言且所有计划步骤均执行通过，才能称为“已验证通过”。
- 用户确认的地址优先，模型不得改为其他目标或跨域绝对 URL。自动试运行不自动跟随重定向，以免超出确认范围。
- 本次覆盖变量纳入候选配置，采用和保存后不丢失必要运行输入。动态唯一值仍在运行时求值，不将一次性的 ID/token 固化为可复用答案。
- 提取失败仍保留已经收到的响应、成功的局部提取项及独立断言。失败步不继续向后执行，也不把其变量交给后续步骤。
- 请求格式、变量和提取路径错误可尝试修复。认证/权限不足、服务故障、网络超时或写入结果未知，以及普通业务断言不符应停止并提示人工处理。
- 负向用例预期 4xx 且实际断言满足时可以通过；不能把所有 4xx 一律判作故障。
- 修复不得删除步骤、交换接口、放宽/删除断言，或通过修改预期变量伪造通过。模型输出本身不能决定验证结论。
- 已执行的远端操作不能随本地取消或事务回滚撤销。每轮尽可能使用唯一测试数据；发生不确定写入时不盲目重放。
- 总任务期限建议由 `AITS_API_GENERATION_TIMEOUT_SECONDS` 控制，默认 1800 秒；每轮启动、流式进度及执行前检查。单次静默模型请求仍受提供方请求超时约束；不能把任务过期描述成一定撤销了远端操作。

## 版本与进度真实性

验证绑定服务端候选及其完整执行上下文。仅采用完全相同的候选时，可将最后一轮真实结果关联到新草稿 revision。用户修改草稿、变量或上下文后，保留历史轮次但立即标记过期。

前端轮询持久状态，而非用动画推算成功。`ready` 仅表示异步任务已结束；是否通过以 `generation` 和 requests 断言结果为准。
