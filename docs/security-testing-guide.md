# 网站与 API 安全测试（第一版）

首页进入「安全测试」，创建或选择安全测试项目。在「安全计划」中按以下流程操作：

1. **配置接口与范围**：手工填写完整 URL，或从有权限的 API 项目导入接口文档端点、本人网页探索任务的请求样本。导入后核对查询参数和普通请求头。允许来源应包含协议、主机和端口，例如 `https://test.example`，不同端口需分别填写。第一版支持 GET/HEAD，不能填写变量占位符。
2. **配置测试账号**：账号 A 是正常访问的基准账号；验证资源越权时，还需要另一个账号 B。填写已有的测试 Authorization、Cookie 或其他认证请求头。普通业务请求头放在接口中；第一版不支持 URL 中的 Token 等认证参数，以免匿名请求继承登录状态。编辑已有计划时默认保留凭据；选择替换会整体替换 A/B，选择清除则移除全部凭据。
3. **声明预期与资源证据**：需要登录的接口勾选「需要认证」；测试账号 A 私有资源时声明该资源仅属于 A。建议填写能辨认受保护资源的 JSON 路径，例如响应 `{"data":{"id":123}}` 对应路径 `body.data.id`、预期值 `123`。字符串预期值需带 JSON 双引号，例如 `"order-123"`。证据应指向私有资源标识，不能只用常见的成功码或空值。
4. **生成并审阅检查计划**：选择模型后，AI 从受控候选检查中选择并解释；不选择模型则生成规则计划。模型只接收接口编号、方法、认证意图和是否配置资源证据，不接收账号凭据、目标 URL 参数或业务响应。生成完成后勾选要执行的检查。
5. **执行与查看证据**：查看基准、匿名、无效认证、账号 B 或跨域来源请求的状态码、耗时和响应预览。运行期间可停止任务。修改计划会清空旧检查项，需要重新生成；历史执行使用提交时的快照。
6. **导出 HTML**：执行结束后可下载独立 HTML 文件，离线打开，无需登录。报告包含已保存的结果、证据与修复建议，不触发新请求或模型调用。

## 第一版检查内容

| 检查 | 执行方式 | 判定限制 |
| --- | --- | --- |
| 登录与认证 | 账号 A 基准与匿名、无效认证请求比较 | 有正常基准且替代身份仍返回受保护资源证据，才确认风险 |
| 权限与越权 | 账号 B 请求声明仅属于 A 的资源 | 需 A/B 两个账号、资源归属声明及有效基准；不自动猜测其他用户的资源编号 |
| 信息泄露 | 检查有限响应内的敏感命名字段及内部错误特征 | 字段存在可能是正常业务输出，先标疑似，需人工复核 |
| 网站基础配置 | 检查安全响应头、Cookie 属性、两个固定测试来源的 CORS 响应 | 配置观察不直接等同可利用漏洞 |

结果分别显示本项通过、已确认、疑似、未验证、检查出错、已跳过。HTTP 200 不能单独证明业务成功；没有问题也不代表系统整体安全。没有足够证据的检查不会算作通过。

## 执行限制

- 每个计划 1–20 个接口，最多 80 个候选检查；请求预算默认 40 次、最高 100 次，包括基准与各变体。相同接口的相同基准在单次任务中复用。
- 默认 1 次/秒，范围 0.1–2 次/秒；单请求默认 10 秒，最多 30 秒；排队上限 5 分钟，单任务执行总时限 10 分钟。
- 不跟随重定向、不使用服务器环境代理。私网地址需在计划中启用；云元数据及链路本地等地址始终禁止。DNS 解析后固定连接地址，HTTPS 保留证书与主机名验证。
- 单个响应最多读取 64 KiB，预览进一步限制长度；截断响应不能用于确认受保护资源证据。账号认证信息加密保存，响应证据脱敏后保存。导出前仍应核对报告中的业务内容。
- 第一版不自动执行登录，不支持 POST/PUT/PATCH/DELETE、文件上传、注入探测或破坏性验证。GET/HEAD 接口也应由使用者确认其业务作用与测试范围。
- 计划编辑需要编辑权限，生成需要编辑及执行权限；执行需要执行及报告权限。查看执行详情、导出报告需要报告权限。

## 本地服务

安全测试复用后端 HTTP/WebSocket 和 Celery，不依赖性能控制器或性能节点。只启动所需服务：

```sh
./platform start backend celery
./platform status
```

本次工作已停止 `controller` 和 `caddy`。后续需要性能测试时再按性能模块部署说明启动；不要为了安全测试而启动这些服务。
