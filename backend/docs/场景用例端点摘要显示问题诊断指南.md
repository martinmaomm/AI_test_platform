# 场景测试用例"涉及端点摘要"显示问题诊断指南

## 🔍 问题描述

测试用例 ID 138（最新生成的场景测试用例）的"涉及端点摘要"列显示的是 **API路径** 而不是 **中文摘要信息**。

**当前显示**：`/api/users/register`、`/api/users/login` 等

**期望显示**：`用户注册`、`用户登录` 等中文摘要

---

## 🎯 可能的原因

### 原因1：数据库中没有这些端点的记录

AI生成的测试用例使用的端点路径（如 `/api/users/register`）可能在数据库的 `api_testing_apiendpoint` 表中不存在。

**为什么会这样？**
- AI根据用户需求自由生成了端点路径
- 这些端点可能还没有通过"API规范管理"功能导入到系统中
- 或者导入时使用的路径格式不一样

### 原因2：路径格式不匹配

数据库中存储的路径可能是：
- `/users/register` （没有 `/api` 前缀）

而AI生成的路径是：
- `/api/users/register` （有 `/api` 前缀）

虽然后端有三种匹配策略，但可能还是没有匹配上。

### 原因3：项目关联问题

端点存在于数据库中，但属于不同的项目，导致查询时被过滤掉。

---

## 🔧 诊断步骤

### 第1步：检查数据库中是否有这些端点

**操作**：在 Anaconda Prompt 中执行以下命令

```bash
# 切换目录
cd /d d:\dev\proj\aits-system\backend

# 激活环境
conda activate aits-backend

# 执行检查脚本
python check_users_endpoints.py
```

**预期输出**：
- 列出所有包含 'users' 的端点
- 显示特定路径是否存在
- 如果存在，显示其摘要信息

**判断**：
- 如果输出 `✗ 不存在`，说明数据库中没有这些端点 → **跳到解决方案1**
- 如果输出 `✓ 存在`，说明端点存在但没有匹配上 → **跳到解决方案2**

### 第2步：检查测试用例 138 的详细匹配情况

**操作**：在 Anaconda Prompt 中执行

```bash
python check_test_case_138.py
```

**预期输出**：
- 测试用例的 `involved_endpoints` 字段内容
- 每个端点的匹配情况（精确匹配、去/api前缀、加/api前缀）
- 项目下所有用户相关的端点列表

**判断**：
- 查看哪些端点没有匹配到
- 查看数据库中实际存在哪些用户相关的端点
- 对比路径格式的差异

---

## ✅ 解决方案

### 解决方案1：导入API规范（推荐）

**适用情况**：数据库中没有这些端点的记录

**步骤**：

1. **准备API规范文件**（OpenAPI/Swagger JSON或YAML）
   - 确保文件中包含所有需要的端点
   - 确保每个端点都有 `summary` 字段（中文摘要）

2. **导入API规范**
   - 访问：`http://localhost:5173/api-testing/api-specs`
   - 点击"上传规范"按钮
   - 选择你的API规范文件
   - 导入后系统会自动解析并创建端点记录

3. **重新执行数据修复**
   ```bash
   cd /d d:\dev\proj\aits-system\backend
   conda activate aits-backend
   python manage.py fix_scenario_fields
   ```

4. **刷新页面验证**
   - 按 F5 刷新浏览器
   - 查看"涉及端点摘要"列是否显示中文摘要

### 解决方案2：手动添加端点（临时方案）

**适用情况**：只有少数几个端点缺失

**步骤**：

1. **访问API规范管理页面**
   - `http://localhost:5173/api-testing/api-specs`

2. **找到或创建对应的API规范**

3. **手动添加端点**
   - 填写：方法（POST/GET等）
   - 填写：路径（如 `/api/users/register`）
   - 填写：摘要（如 `用户注册`）
   - 保存

4. **重新执行数据修复**（同解决方案1）

### 解决方案3：修改路径匹配逻辑（技术方案）

**适用情况**：端点存在但路径格式不一致

**步骤**：

1. **查看诊断脚本输出**
   - 确认数据库中端点的实际路径格式
   - 例如：数据库是 `/user/register`，AI生成的是 `/api/users/register`

2. **增强匹配策略**
   - 编辑 `backend/apps/api_testing/serializers.py`
   - 在 `get_involved_endpoints_with_summary` 方法中添加更多匹配策略
   - 例如：模糊匹配、正则匹配等

3. **重启Django服务器并刷新页面**

### 解决方案4：重新生成测试用例（快速方案）

**适用情况**：当前测试用例可以重新生成

**步骤**：

1. **确保API规范已导入**（参考解决方案1）

2. **删除当前测试用例**
   - 在场景测试用例列表中删除 ID 138

3. **重新使用AI生成**
   - 访问：`http://localhost:5173/api-testing/scenario-generator`
   - 输入相同的需求
   - AI会基于已导入的API规范生成测试用例

4. **验证新生成的测试用例**
   - 查看"涉及端点摘要"列是否正常显示

## ❓ 常见问题

### Q1：为什么AI能生成这些端点，但数据库中没有？

**A**：AI是基于用户需求和自身知识生成的，不会检查数据库。它可以自由创造端点路径。

### Q2：如果我没有API规范文件怎么办？

**A**：可以：
1. 手动添加端点（在API规范管理页面）
2. 从后端代码生成API规范（如果使用Django REST Framework的schema功能）
3. 临时接受显示路径而不是摘要

### Q3：修复后还是显示路径怎么办？

**A**：
1. 确认Django服务器已重启
2. 强制刷新浏览器（Ctrl+Shift+R）
3. 检查浏览器控制台是否有错误
4. 查看Django日志中的调试输出（`logs/django.log`）
