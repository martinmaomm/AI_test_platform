# 项目计划任务

## 业务规则

- 测试类型由当前项目决定，表单不再重复选择。只支持 UI 和 API，未实现的 App 入口移除。
- 打开创建弹窗即加载当前项目套件。空、停用、归档套件不可选；跨项目、重复或已删除的 ID 由后端拒绝。
- 按表单中的套件顺序执行；每个套件结束后才派发下一个，某个套件测试失败仍继续后续套件。套件内部复用已有执行器，不改脚本生成流程。
- 同一计划任务上一轮未结束时拒绝重复启动。暂停只阻止后续自动触发，不中断正在执行的一轮；暂停任务仍可手动执行。
- UI 脚本使用自身网址和已有用例/套件变量，不选择环境。API 任务仍需当前项目已启用的 API 环境。
- 执行结束复用平台原生报告和通知；零用例、全跳过、验证未完成、派发失败不能显示为全部通过。
- 普通成员按项目的编辑、执行和报告权限操作；选择的套件、环境和通知对象均受项目归属校验。

## 执行时间

Cron 使用 5 段：`分 时 日 月 周`，支持数字、`*`、范围、逗号和正整数间隔。星期 `0` 和 `7` 均表示周日。字段超限、零间隔和无效日期在保存前拒绝。

页面的下次时间与 Beat 使用同一个 Celery Cron 解析器和 `CELERY_TIMEZONE`（当前 `Asia/Shanghai`），不依赖 `croniter`。当日期和星期同时指定时，遵循 Celery 的同时满足规则。

## 部署与启动

先停止旧后端和 Celery，在 backend 虚拟环境执行：

```bash
python manage.py migrate
```

随后重启后端、Celery worker，刷新开发前端。迁移仅收紧状态/类型选项，不删除任务或执行记录，不需要下载新的 Python 依赖。

自动到点执行还需要独立的 **Celery Beat 调度进程**。worker 负责执行，Beat 负责看时间、向队列派发任务：

```bash
celery -A config worker --loglevel=info --pool=solo
```

另开一个终端，激活同一虚拟环境：

```bash
celery -A config beat --loglevel=info --logfile=logs/celery-beat.log
```

同一数据库只运行一个 Beat。启动 Beat 会实际执行已启用的任务，请先确认任务的套件和执行时间。暂停任务不会自动执行。未运行 Beat 时仍可手动触发，但不会到点自动运行。

### 页面服务状态检测

Beat 的项目默认调度器继承数据库调度器，在调度循环正常完成后每 10 秒向共享 Redis 缓存记录心跳；页面可见时每 15 秒检测，离开页面或隐藏标签页后停止轮询。

- 没有心跳或心跳超过 60 秒：显示“定时任务服务未启动或已离线”。正常停止后通常在约 60–75 秒内显示提示。
- 收到新心跳：自动收起提示，也可点击“重新检测”。
- 检测接口或 Redis 出错：显示“定时任务服务状态检测失败”，不误报为确定离线。
- 心跳只说明 Beat 调度循环近期在运行，不代表 worker、被测网站正常，也不保证任务已执行成功。提示不禁用编辑、保存和手动执行。

**升级后重启后端和 Beat，无需新增迁移或依赖。旧启动命令中的 `--scheduler django_celery_beat.schedulers:DatabaseScheduler` 必须移除**，否则会绕过项目默认调度器，无法上报心跳。使用上方不带 `--scheduler` 的命令。不要同时保留旧 Beat 再启动新实例。

本次防重入针对同一个计划任务，不是全平台分布式串行队列。当前部署继续使用一个 `--pool=solo` worker，可使不同任务在同一 worker 顺序处理；不要把多 worker 当成已实现全平台严格串行。进程被强杀、消息丢失等情况不自动重复执行有副作用的脚本，需要检查执行记录与服务状态后人工处理。

## 验收与边界

自动回归使用隔离 SQLite、模拟队列和本机临时页面；不连接 NAS、Redis、AI、通知渠道或被测网站。真实数据库迁移与 Beat 启动交由用户完成。

同日服务检测增量验收：后端 390 项回归、前端 133 项单测及生产构建通过；隔离浏览器验证无心跳警告、接口异常提示和恢复后收起提示。未启动实际 Beat，也未读写真实 Redis。

- UI 项目打开创建弹窗即显示已有套件，且无测试类型/环境下拉框。
- API 项目仅显示 API 套件并要求合法环境。
- 多套件排序保存后不变，失败后继续；重复启动明确返回冲突。
- 暂停立即停用对应 Beat 记录，恢复启用重新校验配置。
- 无权限、无套件、接口失败和无效 Cron 明确提示。
