# 保留原节点记录的简化重装

用户已选择继续使用原节点，保留历史。页面取代之前的主机升级工具，改为“停止并删除旧容器 → 生成一条新版 Docker 安装命令”。不再需要宿主机 Python、下载升级脚本或保留回退容器；旧镜像和身份卷不必先删除。

## 契约

- 管理员 `POST nodes/{id}/reinstall/` 必须携带 `confirm_old_container_removed: true`。该确认由用户完成；平台不尝试远程确认或删除容器。
- Project → Node 锁顺序与运行创建一致。有任何排队、准备、执行、停止中运行即拒绝；已吊销、删除或从未注册节点不能调用重装接口。
- 同一事务中先核验发行及命令，再清空旧长期凭证、注册/心跳/版本和资源状态，生成新的 15 分钟注册凭证。保留 UUID、名称、项目、网络位置、创建时间和全部历史记录。失败不改变原身份；旧心跳按原认证摘要复核后拒绝。
- 复用既有安装响应与临时弹窗，GET 不回显凭证或命令。新身份卷以本次注册 token 的 SHA256 前 16 位区分；每次重新签发产生新卷，避免旧 `identity.json` 跳过注册。
- 新版固定容器名仍为 `performance-node-{uuid}`，不猜测旧安装器的实际容器名。用户在原管理工具中删除旧容器，新容器按标准安装参数启动。
- 单用户验证资格限定在本次注册之后，即使 UUID 和 Agent 版本相同也必须重验，历史验证记录保留。

## 前端与验收

已注册节点显示“重新安装”。两步说明、旧身份失效说明及“我已停止并删除旧容器”勾选共同构成明确操作确认。生成期间禁止重复提交和关闭；请求返回须仍属于同一项目/节点/弹窗。保留临时安装命令，并允许后续轮询更新待注册→在线状态。

验证包括后端权限/事务/失效凭证与历史保持、真实 Vue/Django 重装注册流程，以及已发布 0.4.0 镜像在 amd64/arm64 Docker 中的同节点新卷注册和心跳。测试使用隔离记录和临时 TLS 服务，不轮换真实节点凭证，不发压。

无需数据库迁移或 Agent 镜像重发。原主机升级脚本及对应公开路径从当前流程移除；旧验收文档保留为历史，可在其功能提交上复现。
