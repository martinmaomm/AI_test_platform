# 性能节点镜像版本标签与安装流程验收

## 改动

网页原先只执行 `docker run repo@sha256:...`，本地镜像没有版本标签，`docker images` 会显示 `<none>`。现在提供一条完整的可复制命令，依次执行：

```sh
docker pull <固定索引摘要> && docker image tag <固定索引摘要> <仓库:版本> && docker run <原部署参数> <固定索引摘要> start <原注册参数>
```

三段命令分别安全引用，前一步失败时后续不执行。标签用于辨认镜像；实际拉取与启动继续固定摘要。CA 指纹、注册令牌、身份卷、容器权限及资源限制保持原逻辑，新安装和原节点重新安装共用此流程。网页显示版本标签，并提示整条复制执行。

发布流程在固定多架构索引及匿名验收通过后，添加同仓库的简洁版本标签，例如 `martinmao9/performance-node:0.4.1`。已有标签必须与固定索引的 digest 和成员完全一致；相同则复用，不同则拒绝覆盖。已发布 manifest 的固定索引不得被重新绑定，固定 tag 缺失时也不会擅自重建。发布及匿名回读全部通过后才记录 `registry_version_ref`；安装端兼容缺少该字段的原清单，存在时严格校验仓库和版本。

节点程序仍为 0.4.1，管理协议 3、快照 4、运行时及镜像内容均不变。无需数据库迁移，也无需为此重新安装已运行的节点；远端已有镜像需要另行打标，或执行之后生成的安装命令，才会显示本地版本标签。

## 验证

| 检查 | 结果 |
| --- | --- |
| 发布单元测试 | 38 项通过；覆盖同名冲突、原索引漂移、幂等、匿名失败及成功后记录 |
| 安装与重装离线测试 | 36 项通过；覆盖新旧 manifest、错误标签、真实 shell 参数引用和失败短路 |
| 性能 API 回归 | 30 项通过，无数据库迁移变化 |
| 前端测试与构建 | 工作区 23 项、SSR 1 项通过，生产构建通过 |
| Vue/Django/Chrome 隔离重装 | 新格式 manifest 可用、标签显示、完整命令复制、原节点与历史保持、凭据不持久化通过 |
| arm64 真实 Docker | 生成命令实际执行；RepoTags 包含 0.4.1，tag 与摘要一致，容器按摘要运行，重启不重复注册 |
| amd64 真实 Docker | 同上，通过本机架构仿真验证，未在远端设备执行 |
| 独立审查 | 已记录固定索引被重新绑定、新 manifest 被旧字段校验拒绝两处问题均已修复复验 |

真实 Docker 验收使用 `backend/scripts/verify_performance_tagged_install.py`，只连接临时 HTTPS 模拟平台并使用随机测试身份；临时容器和卷全部清理，已验证的本地版本标签保留。未操作真实节点容器、轮换真实凭据或向业务目标发压。
