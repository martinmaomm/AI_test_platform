# 项目知识库使用与验收

## 1. 范围

入口是 UI 自动化项目内的“项目知识库”。项目资料供两个独立功能使用：生成**手工测试用例**，以及**项目知识问答**。
手工用例不能运行 Python，不能加入自动化套件；问答不会启动浏览器、访问文档网址或把回答写回资料库。

现有 API 知识库及 WebUI 自动化脚本链路保持原状。新工作区不自动迁移旧资料；旧文件资产保留。

## 2. 升级

先停止旧 Celery worker，在项目 `backend` 目录激活虚拟环境后运行：

```bash
source .venv/bin/activate
python -m pip install -r requirements.txt
python manage.py migrate project_knowledge
```

新增依赖 `openpyxl==3.1.5` 用于 XLSX 导出。随后在各自终端重启服务：

```bash
python run_asgi.py
```

```bash
celery -A config worker --loglevel=info --pool=solo
```

Celery 的任务清单应出现 `project_knowledge.execute_task`。前端开发模式刷新页面即可；生产部署需要重新执行 `npm run build` 并发布产物。

迁移是新增表及关联，不执行清库。修改 `.env` 后需要重启后端和 Celery：

| 配置 | 含义 |
| --- | --- |
| `PROJECT_KNOWLEDGE_ENABLED=true` | 新知识工作区写入及任务提交开关 |
| `KNOWLEDGE_TOTAL_TIMEOUT_SECONDS=1200` | 单个知识任务总时限；限制为 30–1500 秒，从 worker 开始处理时计算 |
| 模型 `extra_config.timeout` / `LLM_TIMEOUT_SECONDS` | 单次模型请求时间上限，不会因为任务总时限较长而自动增大 |

新任务复用串行 Celery 队列，正在生成自动化脚本时知识任务可能排队，反之亦然。首版不改变全局并发。

## 3. 准备项目资料

1. 选择项目，上传主需求、业务规则、操作说明等文件；类型与模块只是分类。
2. 点击“处理文档”。正文解析成功后，即使索引失败，也可以预览正文和使用仅正文生成模式。
3. 检查“章节 / 来源”，确认重要规则和表格内容没有遗漏，再用于生成或问答。

支持 UTF-8 TXT / Markdown、DOCX、可提取文字的 PDF、XLSX；上传限制 50 MiB。旧 DOC / XLS 先转换。Office 文件展开体积另限 100 MiB，避免小压缩文件占满服务内存。
不提供 OCR；纯扫描 PDF 或检测到部分图片页缺少文字时会提示处理。复杂排版、图片中的规则及表格视觉结构仍需人工核对，解析成功不代表文档内容完整无误。

语义索引读取已启用的 RAG 配置（优先默认配置），使用其中的 embedding 模型。

- Chroma：collection 为 `project_knowledge`，使用配置的存储目录；目录为空时使用 `backend/project_knowledge_chroma_db/`。
- Milvus：collection 为 `<原配置集合名>_project_knowledge`；不会覆盖原 API 集合。
- embedding 实例在 Celery 进程内复用，配置改变后重建。模型首次加载可能较慢；本地已有缓存不等于无需内存。
- 更换 embedding 模型、维度或向量存储位置后，应重新处理相关资料；不要把旧索引的“就绪”状态当成新索引已建立。首版不自动迁移向量存储。

更新资料创建新版本，不覆盖旧正文。旧版本立即失去新检索资格；历史结果保留当时的来源快照，并提示来源状态。
停用资料立即排除新检索，重新启用可继续使用未改变的索引；删除资料则在后台清理索引。清理失败不影响数据库的检索隔离，可重试清理任务。
删除不等于彻底抹除历史引用，若要清除历史内容，需要另行明确范围。

## 4. 生成手工用例

1. 选择主需求、章节和生成目标；首版由用户确定范围，不由模型自动决定“全部需求”。
2. 补充资料用于检索关联规则；查看本次包含与排除的资料后选择模型。
3. 后台逐段整理测试点、生成用例。不是只取相似度最高的几段，因此末尾章节也会被顺序处理。
4. 草稿检查标题、步骤及预期、来源、待确认项；编辑后选中保存，正式用例再单独管理。
5. 从生成记录恢复草稿；失败或取消后的有效部分仍可保存，未处理章节通过新任务继续。

“资料处理覆盖”只是选定章节的处理进度，不等于需求覆盖率或测试通过率。保存默认未审核，模型建议仍需人工判断。
重复保存同一草稿不会创建重复用例，也不会覆盖后来编辑的正式用例。导出 XLSX 包含步骤、预期、来源和待确认项，公式触发内容按文本处理。

## 5. 项目问答

新建会话、选择范围和模型后提问。默认使用项目当前启用资料；有未建立索引的资料时，需等待处理或明确排除，不会悄悄漏掉后直接回答。
回答生成期间引用尚待校验，完成后可以点击来源查看原文和版本。存在无效引用或断流时，保留为待核对／未完成回答。

会话及任务历史仅发起者可见，已保存手工用例按项目权限共享。只读项目成员可以看资料、看用例和创建自己的问答，但不能修改资料或生成共享用例。
资料片段会发送给选中的模型提供商；不要上传不允许外发的资料。引用有效只证明来源存在，语义是否吻合仍需核对。

## 6. 本地验证命令

以下命令在仓库根目录运行，新知识库离线测试会覆盖数据库配置并阻断外部网络：

```bash
backend/.venv/bin/python backend/scripts/test_project_knowledge_offline.py
backend/.venv/bin/python backend/scripts/test_webui_generation_offline.py
```

前端单元测试和构建在 `frontend` 目录运行：

```bash
npm run test:unit
npm run build
```

真实浏览器联调使用临时数据库、真实本地 API、确定性模型桩与合成文件，需先构建前端，然后运行：

```bash
backend/.venv/bin/python backend/scripts/test_project_knowledge_browser.py
```

浏览器脚本默认使用当前 macOS 上的 Google Chrome；其他系统可设置 `TEST_CHROME_EXECUTABLE` 指向本机浏览器可执行文件。
截图保存在已忽略的 `backend/logs/knowledge-browser-check/`，临时数据库、登录 Profile 和测试令牌随测试结束清理。

浏览器测试不调用真实模型或被测网站；不能据此声称真实模型的用例质量已验收。当前 MariaDB 迁移验收使用独立临时容器，不是 NAS 数据库；实际 Milvus、真实模型及用户文件仍需上线前验证。

### 建议网页验收样本

准备三份小文档：主需求写“用户名必填且不可重复”，权限规则写“只读角色不能新增”，补充说明写一个与主需求冲突的规则。
主需求最后一节再写一个与前文相似度较低的规则，并保持在选择范围内。

- 生成：确认所有选定章节被处理；来源可点开；末尾规则没有被 top-k 检索漏掉。
- 问答：分别问有依据的规则、未规定的密码长度、两份资料的冲突，确认不是都输出确定答案。
- 修改文档后重问，不能命中旧规则；历史引用应标记旧版本。
- 取消任务、刷新页面、重复保存草稿后确认结果不丢失、不重复。
- 用只读成员和另一个项目分别验证权限。

## 7. 暂停与回退

将 `PROJECT_KNOWLEDGE_ENABLED=false` 后重启服务，禁止新的修改和任务提交；历史仍可查看，本人任务仍可取消。
这不会立即强杀已经发给提供商的请求。取消后不再接收后续结果，等待当前调用退出，必要时正常停止 worker。
回退不要求删表、逆向迁移或重置向量库。已保存数据和索引保留供排查，不清理原 API RAG 或自动化脚本。
