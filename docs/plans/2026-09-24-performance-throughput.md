# 运行结果吞吐量第一版

用户批准把平均 RPS 改为明确的请求吞吐量名称，增加各接口吞吐量、区间趋势和峰值。数据吞吐量（KB/MB 每秒）不在本版；沿用请求尝试计数，包含成功、失败、准备步骤和已有的发送前处理失败，不把请求吞吐量称为业务 TPS。

## 数据与计算

- 从已保存的运行/节点累计指标及最近 400 个采样推导，只读计算，不更改历史记录或节点协议。已有记录有足够数据即可展示，节点无需升级。
- 平均请求吞吐量：沿用有效累计 RPS。各接口平均值：接口累计请求数除以同轮运行统计时长，不使用接口自身首末请求之间的时间。
- 区间请求吞吐量：相邻有效采样的累计请求增量除以统计时间增量。无足够数据显示未知；零请求增量且时间有效时才为零。
- 优先使用节点运行统计的 elapsed_seconds；节点旧数据可从同轮累计 requests/rps 还原相同分母。没有这类时长时，只能在同类采样时钟间计算，禁止混用运行时长与墙上时钟。
- 首点、缺失、非法数值、重复时刻、倒序和计数回退不制造区间或尖峰；无效样本之间不跨点拼接。重复终态采样不重复计入。
- 峰值名称为“采样区间峰值”，只取保留的有效区间，不能当作某一秒的瞬时峰值或被测服务的最大承载能力。长测早期采样可能已截断，采样间短峰也可能未显示。

详情接口在运行及节点对象增加只读 `throughput`：

```text
average_rps: number | null
peak_interval_rps: number | null
valid_intervals: integer
intervals: [{timestamp, rps: number | null, interval_seconds: number | null}]
endpoint_rps: [number | null]
```

`intervals` 与对应的最后 400 条原采样逐项对齐；`endpoint_rps` 与接口明细逐项对齐。列表接口保持简洁，不添加派生序列。

## 展示与 AI

总览使用“平均请求吞吐量（次/秒）”及“采样区间峰值（次/秒）”，保留问号说明。接口与节点表补平均吞吐量。图表同时展示平均值和区间值，空值断线，不平滑吞吐量线条；提示区间长度及最近保留采样限制。全部节点和单节点视图使用各自的统计范围。

新 AI 分析复用相同计算函数，将峰值、区间趋势和接口吞吐量作为匿名统计证据，保留采样局限说明。既有分析记录不重写，也不自动重跑模型。
