# 优化与技术债跟踪

## 正式应用前：报告访问、多用户权限与隐私

- 记录日期：2026-09-15；状态：报告与隐私策略暂缓，P-02 的简单用户管理已按方案 A 实施；正式应用前仍需重新评审与验收。
- 当前决定：调试阶段允许独立报告匿名只读访问，接受报告中测试数据、日志、截图及测试凭据可见。此决定不代表项目配置、脚本修改、执行、删除或 AI 修复也可以公开；这些管理权限继续保留。
- 报告实现与验证见 [报告公开访问验收](verification/2026-09-15-public-reports.md)。下列条目分别标明已实施与后续待办，不表示所有列出的风险均已复现。

### P-01 报告访问与分享策略（待设计）

- 现状：知道或猜到报告地址即可读取内容，无登录、项目成员、分享密码或到期时间限制；转发链接也能访问。
- 上线前确定：内部报告是否恢复登录和项目权限；外部分享是否采用不可预测、可撤销、可过期的授权链接。截图、关联子报告和下载资源必须遵守同一授权规则，不能只保护页面入口。
- 验收：覆盖匿名、非成员、成员被移除、链接过期/撤销、猜测 ID 和直接访问附件；分享访问不得获得管理权限。撤销无法收回接收者已下载或另存的内容，需明确说明。

### P-02 多用户管理与权限边界（简单版已实施）

- 按用户确认的方案 A，仅保留管理员、普通用户两个可选角色，初始化超级管理员受保护且独占管理员授予权；管理员管理全部项目、普通用户操作已分配项目。未建设项目管理员或报告查看者等额外角色。
- 已提供账号创建/编辑/启停/密码重置和多人多项目分配；后端统一项目权限、共享可用 AI 配置并隔离配置密钥。注册或个人资料不能提权，停用后的旧 token 不能用于新请求/新建 WebSocket；项目移除和角色降级按最新关系检查。
- 使用方法见 [用户管理与项目分配](user-management.md)，设计见 [方案 A](plans/2026-09-15-simple-user-management.md)。公开报告策略不变；正式应用前仍需决定更强会话撤销、正在运行任务的停用策略和操作审计。

### P-03 敏感信息与凭据处理（待评估、待实施）

- 检查报告、请求响应、运行日志、生成/修复对话、浏览器轨迹、截图、导出文件及邮件摘要中的密码、Token、Cookie、API Key 和个人信息。
- 上线前确定凭据引用、存储及展示规则；区分内部调试详情与可分享报告。截图需要单独处理，文本替换不能代替图像隐私检查。
- 评估传给第三方模型/MCP 的数据范围，避免无关信息随上下文发送；用明确标记的测试数据验收各输出渠道，不以关键词过滤阻断正常探索和生成流程。

### P-04 历史数据与保留期限（待评估、待实施）

- 新规则不能自动消除已有明文数据。盘点数据库、日志、截图、轨迹、导出及备份，确定保留期限、访问方式和清理范围；需要时轮换曾公开的凭据。
- 历史清理或凭据轮换须另行确认具体对象和影响，不因本条记录自动删除数据。验收同时检查旧报告、旧附件及备份，不只检查新生成记录。

### P-05 报告链接与上线配置（已明确暂缓）

- 报告链接地址问题按用户要求暂不修改。正式部署时核对 `FRONTEND_BASE_URL`、域名、HTTPS、反向代理和开发模式配置，确保邮件链接对实际收件人可达。
- 验收：从不同设备打开邮件中的真实报告链接；按届时确定的访问策略检查报告和截图，不以本机打开成功代替收件人访问验证。

除 P-02 的方案 A 用户管理外，上述事项仍仅记录；不重写当前生成、调试、执行流程，不重新启用隐私拦截，不清理历史数据或发送测试邮件。

## API 自动来源确认与 HTTP 重定向

- 发现日期：2026-09-09。
- 范围：API 网页探索自动模式的跨主机来源确认；不是 requests 执行层或 UI 脚本生成层。
- 根因：当前 Chromium Playwright 路由仅将首跳交给 `context.route`，已放行请求的后续 HTTP 重定向由浏览器继续，不能靠首跳授权宣称拦截了全部网络请求。307/308 可能转发原方法与正文。
- 本次处理：直接 fetch/XHR 请求支持发送前确认，重定向后续仅保留受限元信息，不作为完整可执行证据；页面和使用文档明确标注仅限可信测试站点，不支持把此机制当作重定向或 SSO 的安全隔离层。
- 已知风险：重定向请求可能在用户审批前已经发出，元信息记录不能撤销网站写入。不能通过重复登录、代理重放或补抓正文掩盖此限制。
- 后续根因方案：单独评估 Chromium CDP 响应阶段 Fetch 拦截与 Playwright 路由的交互，在重定向发生前确认目标；须测试 302/303/307/308、相对 Location、多跳、Cookie、方法与正文保留、取消及无重放，再改变支持范围。本次未引入该底层架构改动。
- 2026-09-12 回归：已补齐直接文档导航和新窗口首请求的来源检查。尝试响应代取后发现 Chromium 将内网页面当作合成响应，导致原本可用的回环 API 被网络地址空间策略拒绝；该实现已撤回，不授予额外浏览器权限、不禁用网络安全功能。11 项采集测试（含真实 Chrome）通过；重定向仍保持上述边界。

## Element Plus 数字输入框动态禁用状态

- 发现日期：2026-09-09。
- 范围：API 网页探索页的探索总时限输入框。
- 触发：输入框初次挂载时页面仍在加载，`disabled=true`；随后解锁。
- 本地证据：当前安装版本 `element-plus/es/components/input-number/src/input-number2.mjs` 只在 `onMounted` 写入内部输入框的 `aria-disabled`，`onUpdated` 只更新 `aria-valuenow`。实际可编辑状态恢复，但可访问性状态仍为禁用。
- 当前处理：按禁用状态为该数字输入框设置组件 key，状态变化时重建控件，使原生状态与 ARIA 状态同步；数值由父级 `v-model` 保留。不改依赖包文件，不升级全项目依赖，不强制绕过浏览器的可用性检查。
- 边界：切换禁用状态会重建该控件并丢失其焦点；加载或提交期间本就不允许输入，已输入数值仍保留。
- 后续：统一升级组件库时，验证动态 `aria-disabled` 已修复后移除此局部处理，保留浏览器回归测试。
