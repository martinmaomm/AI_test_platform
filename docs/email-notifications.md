# 邮件通知配置与验收

UI 与 API 使用同一套邮件服务配置，各项目分别管理自己的邮件接收组。平台只支持邮件通知，不再提供钉钉、企业微信或 Webhook 入口。

## 1. 配置发件邮箱（管理员）

入口：**首页 → 系统配置 → 邮件服务配置 → 新建配置**。

| 字段 | 填写方式 |
| --- | --- |
| 配置名称 | 便于识别的名称，例如“测试平台发件邮箱” |
| SMTP 服务器 | 邮箱服务商提供的主机名；不要填写 `https://`、路径或 `主机:端口` |
| 端口 | 填写服务商要求的 SMTP 端口 |
| 发件邮箱 | 用于 SMTP 认证和发送邮件的邮箱地址；当前不支持独立的登录用户名 |
| SMTP 授权码 | 先在邮箱服务商处开启 SMTP；优先使用服务商提供的授权码，勿直接填写网页登录密码 |
| 加密方式 | `SSL/TLS` 为连接时直接加密（常用 465）；`STARTTLS` 为建立连接后升级加密（常用 587）。以服务商设置为准，平台不提供明文 SMTP 模式 |
| 启用 | 多份配置启用时，**最近更新的已启用配置**用于所有项目；页面标记“当前用于发送” |

保存不会发信。点击 **测试连接** 只检查网络、TLS 和 SMTP 认证；成功不代表收件人已收到邮件。

编辑时授权码留空会保留原值，接口不会返回授权码原文。保存已启用配置可能切换全局发件服务；停用或删除当前配置后，会使用剩余已启用配置中最近更新的一份。没有启用配置时发送会明确报错，不会显示成功。

## 2. 添加收件人（UI/API 项目）

1. 进入项目的 **邮件通知** 页面，点击 **新建邮件接收组**。
2. 填写组名和收件邮箱。多个地址用英文逗号、英文分号或换行分隔；系统校验地址并去重。不要在末尾留下分隔符。
3. 保持“启用”，保存。保存本身不会发送邮件。
4. 点击 **发送测试邮件**，核对确认框中的收件地址后确认发送。
5. 页面显示“SMTP 已接受”后，实际检查收件箱及垃圾邮件目录。只有实际收信才能确认端到端送达。

收件组按项目隔离；发送测试需要项目执行权限，编辑需要编辑权限，删除需要删除权限。停用的接收组不能测试发送，也不能作为新的计划任务通知对象。

## 3. 让计划任务发送结果

在项目 **定时任务 → 创建/编辑任务** 中：

- 选择测试套件；API 项目同时选择执行环境。
- 选择 **邮件接收组**，支持多选。不选则不发邮件。
- 触发条件选择“始终通知”或“仅失败时通知”。
- 定时触发需要 Beat 和 Celery worker；计划任务的“立即执行”完成后也会走通知流程。
- **普通单用例或套件直接手动运行，不会自动发送邮件。**

邮件包含任务摘要、执行结果和平台报告链接，不依赖 Allure，也不会为生成报告重跑测试。查看报告仍需登录，并具备对应项目权限。

`backend/.env` 中的 `FRONTEND_BASE_URL` 必须是收件人能访问的前端地址。填写 `localhost` 会指向收件人自己的电脑；不要填写后端 API 端口。修改 `.env` 后重启 ASGI 和 worker；使用计划任务时一并重启 Beat。网页中的 SMTP 和收件组配置保存后直接生效，不需要重启。

## 4. 常见问题

| 提示/现象 | 检查方式 |
| --- | --- |
| 未配置启用的邮件服务 | 管理员新建并启用 SMTP 配置 |
| SMTP 认证失败 | 检查发件邮箱、SMTP 是否开启、授权码是否正确；这不是平台登录过期 |
| SSL/TLS 协商失败或连接超时 | 核对服务器、端口、加密方式、网络访问和证书链；不要关闭证书验证来绕过错误 |
| 拒绝部分收件人 | 其他地址可能已收到；先检查地址和实际收信，不要直接整组重复发送 |
| SMTP 已接受但未收信 | 检查垃圾邮件、供应商退信及限流；SMTP 接受不等于最终送达 |
| 计划任务没有发信 | 检查收件组启用状态、触发条件、任务是否结束、Celery 日志；普通手动用例运行不触发通知 |
| 报告链接打不开 | 核对前端地址、登录状态及项目权限 |

不自动重试邮件发送，以免网络超时或部分拒收后重复投递。当前也没有独立的邮件发送记录页，发送结果与失败原因以后台日志和实际收信为准。

## 5. 本次升级

在后端虚拟环境执行：

```bash
python manage.py migrate notifications
```

随后重启后端 ASGI 与 Celery worker；若运行 Beat，也一并重启。开发模式前端自动刷新，生产模式需要重新构建发布。

迁移 `0012_email_only_notifications` 确保内置邮件渠道存在，并停用非邮件渠道和接收组；不删除邮件配置、接收组、计划任务关联或执行历史。旧 Webhook 数据仅保留在数据库，不再参与发送或出现在配置接口中。迁移回退不会自动重新启用已停用的历史渠道，避免意外恢复发送。

## 6. 验证边界

离线回归使用临时 SQLite，浏览器验收使用真实页面与 Django API、隔离邮件 outbox；不会连接 NAS、Redis、模型或真实邮箱。另有本地 SMTP 协议测试，使用随机回环端口与临时测试证书，验证 TLS、STARTTLS、认证、中文 MIME 及部分拒收；不关闭生产证书验证。上述验证不能替代真实邮箱服务商的收信验收。

# 在项目根目录执行
backend/.venv/bin/python backend/scripts/test_webui_generation_offline.py notifications scheduled_tasks.test_notification_targets scheduled_tasks.test_environment_contract
backend/.venv/bin/python backend/scripts/test_webui_generation_offline.py notifications.test_smtp_protocol
backend/.venv/bin/python backend/scripts/test_notification_migration_offline.py
npm --prefix frontend run test:unit
npm --prefix frontend run build
backend/.venv/bin/python backend/scripts/test_notifications_browser.py
