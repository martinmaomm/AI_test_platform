# WebUI MCP 智能体稳定性修复设计

## 背景

最新 WebUI AI 脚本生成任务已经能够启动 Playwright `1.57.0` 浏览器、访问目标页面、截图并读取页面内容，但最终仍因 LangGraph 达到 60 次递归上限而失败。

日志确认存在三个独立问题：

1. `playwright_navigate` 未显式传入 `headless` 时，固定版本 MCP 在当前调用链中产生布尔类型校验错误；部署环境应显式传入布尔值 `true`，避免在运行 Celery 的机器上弹出浏览器窗口。
2. 智能体在已经获取足够页面结构后继续重复登录、截图和读取页面，没有及时停止工具调用并输出脚本。
3. 当前代码把所有 `GraphRecursionError` 都误报为“Chromium 未安装”，同时对上游模型 `429` 限流会重新执行整轮 MCP 任务。

## 目标

- 让智能体每次导航时稳定使用布尔值 `headless: true`，以无头模式完成页面探索。
- 控制探索范围，在获取必要页面结构后及时生成 Python Playwright 脚本。
- 对浏览器故障、步骤超限、模型限流和临时网络故障给出准确且不同的错误信息。
- 避免对明确的 `429` 限流从头重复整轮页面探索。

## 非目标

- 不升级或替换 `@executeautomation/playwright-mcp-server@1.0.12`。
- 不增加 LangGraph 的步骤上限。
- 不改动前端接口、数据库结构或 MCP 数据库配置。
- 不调整用户现有 LLM 服务地址和模型配置。

## 方案选择

### 方案 A：仅提高步骤上限

实现简单，但会延长已经超过 12 分钟的失败任务，不能解决错误提示和重复探索问题，不采用。

### 方案 B：修改 npm 缓存中的 MCP 包

可以直接修复 `headless` 默认值，但 npm 缓存不可追踪，重新安装后修改会丢失，不采用。

### 方案 C：项目侧约束智能体并细分错误（采用）

在项目自己的智能体提示和错误分类层完成修复，不修改第三方包，部署可追踪且风险最小。

## 详细设计

### 1. 智能体系统约束

在创建 `MCPAgent` 时增加附加指令，并在任务提示中保持同样的关键约束：

- 调用 `playwright_navigate` 必须显式传入 JSON 布尔值 `headless: true`，不得省略，不得传字符串。
- 页面探索最多使用 12 次浏览器工具调用。
- 获取必要定位器、可见文本和页面结构后，立即停止工具调用并直接输出完整 Python 代码。
- 生成阶段不要求把整个业务流程真实执行成功；单个业务操作失败后最多补充一次页面检查，然后根据已获得信息生成脚本。
- 最终输出只能包含可提取的完整 Python 代码，不继续调用截图、控制台或 HTML 工具。

保留当前 `max_steps=30` 作为最后安全上限，避免复杂页面因硬性降低 LangGraph 上限而过早失败。

### 2. 错误分类

将错误分为四类：

| 错误类型 | 处理方式 | 前端提示重点 |
| --- | --- | --- |
| 浏览器可执行文件缺失或启动失败 | 不重试整轮任务 | 检查浏览器路径、版本和 Celery 环境 |
| `GraphRecursionError` | 不重试 | 页面探索超过上限，缩短任务描述或检查模型是否反复调用工具 |
| 上游模型 `429` 或 `UPSTREAM_RATE_LIMITED` | 不重试整轮任务 | 模型服务限流，按提示等待后重试或更换稳定模型 |
| 临时 MCP 连接、`503`、`504` | 保留有限重试 | 临时服务异常，稍后重试 |

`GraphRecursionError` 的提示不得再包含“安装 Chromium”。

### 3. 日志与可诊断性

- 在初始化日志中记录已应用 `headless:true` 和“工具调用预算”约束，但不记录凭据。
- 错误日志保留底层异常堆栈，WebSocket 只返回简明中文提示。
- 不改变现有 Celery 文件日志配置。

## 测试与验证

### 自动验证

- 对错误分类和用户提示增加聚焦测试，至少覆盖 `GraphRecursionError`、浏览器错误和 `429` 限流。
- 运行相关测试、`python manage.py check` 和 Python 编译检查。
- 执行 `git diff --check`，同时保留并说明仓库中与本次无关的既有换行问题。

### 手工验收

1. 重启 Celery Worker。
2. 在 AI 脚本实验室提交同一条测试描述。
3. 日志中的每次 `playwright_navigate` 必须包含 JSON 布尔值 `headless: true`，且部署机器不应弹出可见浏览器窗口。
4. 浏览器成功访问页面后，智能体应在 12 次以内完成主要探索并输出脚本。
5. 若模型服务返回最终 `429`，前端应提示模型限流，不应再次从头访问页面。

## 风险与回滚

- 部分复杂页面可能需要超过 12 次工具调用；第一版以减少无效循环为优先，后续可根据日志调整预算。
- 无头模式可能与少数存在反自动化、验证码或渲染差异的网站不兼容；遇到此类目标时再单独评估是否增加可配置开关，本次不提前扩展。
- 提示约束依赖模型遵循能力，因此仍保留 `max_steps=30` 的最后保护。
- 本次只修改项目侧 Python 文件和对应测试；回滚这些提交即可恢复原行为，不影响数据库和浏览器资源。
