# 简单用户管理与项目分配（方案 A）

2026-09-15 用户已确认：管理员管理全部项目，普通用户操作已分配项目，保持简单。不建设自定义 RBAC 配置台，不变更报告公开策略。

## 已确认的权限

- 普通用户：只访问加入的项目，协作维护、生成、调试、执行测试内容；不能创建/修改/删除整个项目、不能分配成员，不能访问 AI 实验室配置和全局系统设置。
- 管理员：管理全部项目、普通账号与成员分配、AI 和全局设置，无需逐项目授权。
- 超级管理员：平台初始化的超级管理员账号，包含管理员全部权限，并且只有超级管理员可以授予/撤销管理员身份。它是受保护的账号标记，不增加第三个可选角色。
- 独立报告及执行截图仍公开只读；管理列表、源脚本和写操作不因此开放。

## 首版实现

复用 Django `is_staff` / `is_superuser` / `is_active` 和现有 `ProjectMember`；不增加重复角色模型，不自动提升账号权限，不删除既有项目/用例/执行记录。

1. 全局系统设置新增“用户管理”：搜索分页、创建、编辑、启停、设置新密码、分配项目；不提供物理删除账号。
2. 前后端统一使用只读角色信息。注册、个人资料接口不得自授权限；管理员不能修改其他管理员或超级管理员，超级管理员也不能从管理页停用自身或修改其他超级管理员。个人资料入口保留。
3. 项目分配支持多人多项目，一次提交原子替换目标普通用户的成员关系；新分配成员可维护与执行项目测试内容，删除整个项目仍只限管理员。取消成员后旧 token 不可继续访问该项目，旧创建人字段不作为绕过成员关系的入口。
4. AI 配置由管理员统一管理，`created_by` 仅记录创建人。业务生成页面使用独立安全的可用模型列表；普通成员可使用启用配置，但不得读出密钥或修改配置。生成/探索算法不因角色改动而重写。
5. 已保存的用例、套件、接口资料和执行结果以项目共享，不限创建者。个人生成草稿、问答会话仍保持个人工作上下文，不在本次改成公共聊天。
6. 首页、编辑布局、直达 URL 都有门禁；真正授权由后端实时账号和项目成员状态决定。移除成员/降级后的新请求立即按新权限检查，不承诺自动回滚已执行的网站操作或瞬间中止正在执行的子进程。
7. 没有项目上下文的旧全局文件工具和 task-ID WebSocket 仅管理员可用；普通生成页面继续使用按用户区分的流式通道和按项目授权的状态接口。停用账号不能用旧 token 新建 WebSocket 连接。

## API 契约

- `GET/POST /api/v1/users/manage/`：用户列表与创建；列表分页为 `data.items`、`data.pagination`。
- `GET/PATCH /api/v1/users/manage/{id}/`：读取/修改；角色仅 `admin` / `user`，创建必填密码，修改不传密码则保持原值。
- `GET/PUT /api/v1/users/manage/{id}/projects/`：`{ "project_ids": [...] }`，仅为普通用户分配；管理员天然可管理全部项目。
- `GET /api/v1/ai-core/llm-configs/available/`：已登录业务用户的安全模型选项，不包含 API Key、连接配置或任意扩展参数。

## 验收与发布

- 隔离环境覆盖超管/管理员/成员/非成员/禁用账号；注册与个人资料伪造角色不得提权；管理员不可修改同级账号；无用户物理删除入口。
- 验证批量项目分配、撤销、跨项目 URL/关联 ID、多人访问别人保存的用例及正常生成/执行路径；无效项目 ID 不产生部分分配。
- 普通用户不可直接调用配置管理接口，但安全模型列表和项目业务工作正常；禁用模型不可用。
- 浏览器检查首页卡片、设置门禁、用户管理表单、分页项目选择、撤权后的旧登录状态，以及匿名报告不回归。
- 自动化测试在 Django 初始化前切到临时 SQLite、内存缓存/队列并限制 loopback；不对 NAS 运行测试建库，不调用真实模型或 SMTP。部署只读检查与测试隔离，未经进一步确认不修改真实账号/成员关系。
- 验收后提交中文 commit；确认无正在执行的任务后重启后端和 Celery。仅恢复前一版代码可回退功能；若用户之后已调整成员/角色，回退代码不会自动恢复这些数据，需单独核对。
