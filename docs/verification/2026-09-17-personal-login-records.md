## 真实 HTTP 与页面验证

使用两个本轮临时普通账号与随机密码，不使用或修改既有账号；请求发往本机真实 Vite/后端和实际数据库。

1. 两个密码登录入口保持原响应格式并记录成功登录；错误密码不记录。
2. Token 续期、校验及读取列表不增加记录。
3. 经 Vite 访问时故意发送伪造的 `X-Forwarded-For`、`X-Real-IP` 和 `Expect: 100-continue`，实际记录仍为 TCP 客户端 `192.168.31.205`。
4. 直接通过 LAN 地址访问后端时，未信任的对端不能通过伪造头改变记录 IP。
5. 登录记录接口仅返回本人数据；伪造 `user_id` 参数无效；匿名 401、写入 405、非法分页 400；响应带 `Cache-Control: no-store`。
6. Chromium 打开真实首页，从用户菜单进入“登录记录”，显示登录时间/IP/客户端信息；刷新不新增记录；为临时账号加入分页夹具后，21 条记录能正常翻至第二页。

浏览器验收未模拟 API，截图保存在被 Git 忽略的 `backend/temp/login-records-acceptance/login-records.png`。测试结束删除了本轮临时账号及其关联记录、令牌；剩余临时验收账号为 0，既有账号与业务数据保留。

## 边界

- IPv6、可信多跳链、管理员仅查看自己、记录持久化失败仍可登录等由隔离测试验证；本次真实链路为 IPv4 LAN，不宣称公网 NAT/所有反向代理拓扑均已实测。
- 历史登录不回填；Django Admin 的独立 Session 登录、失败尝试、管理员全量审计、保留期清理不在首版范围。
