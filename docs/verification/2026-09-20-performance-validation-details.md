# 单用户验证逐步明细验收

## 结果与范围

单用户验证原先仅上报聚合统计和最多 20 条失败样本。本次增加完整步骤列表，显示准备/主流程、通过/失败/跳过、实际请求 URL、请求头和渲染后请求体、响应状态/耗时/正文、全部断言的期望及实际值、变量提取结果。失败步骤默认展开，数字与字符串使用不同展示，响应提取成功但整步失败时明确说明值未提交。

节点仅在 validation 模式采集新明细；正式压测继续使用原聚合统计和失败样本。执行策略、断言判定、步骤失败后中止本轮、单用户一轮和正式压测前验证门禁保持不变。

## 数据边界

- 节点在上报前脱敏敏感字段和已知凭证值，后端再次规范结构及大小；正文通常最多展示 8 KiB，过长、嵌套过深、列表过长及读取不完整均明确标注。保留最多 20 步，每步最多 50 条断言和 50 项提取；过大的步骤会进一步压缩预览，仍保留各条检查的结果。
- 明细保存在最新指标内，不复制到每次趋势采样。READ 权限的列表不返回新明细；只有既有 REPORT 权限的详情接口返回 `validation_steps`，未增加数据库字段或迁移。
- 历史缺失响应不推测、不回放；详情页说明重新验证条件，仍可查看原有失败证据。新页面使用转义文本展示正文，HTML/脚本响应不会被执行。

## 验证证据

- 节点测试 62/62 通过，含新增的断言逐条结果、失败后跳过、未提交提取值、读取不完整、凭证脱敏、原始文本和数字凭证、UTF-8 截断、报表大小约束、正式压测不采集逐步明细。
- 隔离 Django 测试 83/83 通过，覆盖执行契约、控制器、报告权限、列表不返回正文、趋势不重复持久化明细、旧节点升级提示及安装配置。
- 本机真实 HTTPS Agent → mTLS Locust → 回环 HTTP 夹具端到端通过：一次准备登录、一次主请求、令牌与 Cookie 传递、通过验证、正式压测、停止、两条断言失败以及第三步跳过。确认最终响应正文及断言结果已从实际执行器传到数据库和详情 API，正式压测仍不生成逐步明细。
- 真实 Vue / Django / Chrome 浏览器回归通过：失败步骤自动展开、响应及截断提示、`3` 与 `"3"` 区别、跳过原因、脱敏提取值、历史记录提示、正式压测视图及 HTML 转义。无页面错误，无外部目标请求。已查看截图 `backend/temp/performance-validation-browser/failed-step.png`。
- 前端相关单测 23/23 通过，生产构建通过，保留既有大分块提示。`git diff --check` 通过。
