# 场景测试用例"涉及端点"和"涉及模块"功能实施指南

## 📋 功能概述

为场景测试用例添加两个新字段：
- **involved_endpoints**: 场景涉及的端点列表 `[{"method": "GET", "path": "/api/user/login"}]`
- **involved_modules**: 场景涉及的模块列表 `["用户模块", "订单模块"]`

这两个字段会：
1. 自动从 `request_data` 中的步骤提取
2. 在列表页面展示，方便筛选和管理
3. 支持通过端点和模块快速筛选场景用例

## 📊 数据提取逻辑

### 后端自动提取（推荐）

创建/更新场景用例时，后端会自动：

1. 从 `request_data` 提取端点：
```python
{
  "steps": [
    {
      "name": "用户登录",
      "request": {
        "method": "POST",
        "url": "/api/user/login"
      }
    }
  ]
}
```

2. 从端点路径提取模块：
   - `/api/user/login` → "用户模块"
   - `/api/order/list` → "订单模块"

3. 如果无法从端点提取，尝试从标题提取：
   - "用户注册流程" → "用户模块"

### 前端显示（后备方案）

如果后端字段为空，前端也可以实时提取并显示。

## 📝 注意事项

1. **向后兼容**: 现有的场景用例不会自动填充这两个字段，需要运行 `update_scenario_involved_fields` 命令
2. **自动提取**: 新创建/更新的场景用例会自动提取这些信息
3. **手动指定**: 前端也可以在创建时手动指定这两个字段的值

## 🐛 排查问题

如果"涉及端点"和"涉及模块"显示为空：

1. 检查 `request_data` 字段是否有数据
2. 检查 `request_data` 格式是否正确
3. 运行数据迁移命令更新现有数据
4. 查看浏览器控制台是否有JavaScript错误
5. 查看Django日志是否有Python错误
