# 性能验收、轻量失败诊断与离线 HTML 报告

## 范围与使用方式

本轮沿用现有并发能力，新增三个功能，不调整发压节点协议或发行包。

1. 编辑压测计划时，可设置 P95 响应时间上限、错误率上限、平均请求吞吐量下限。每项均可留空，错误率允许为 0。全部留空时显示“未配置验收标准”，不自动判定达标。
2. 正式压测详情展示轻量失败定位和排查建议，现有 AI 结果分析同时读取这些证据。不重复请求被测系统，不自动调用模型。
3. 正式压测结束后，在执行详情点击“导出 HTML 报告”。报告是包含样式和 SVG 图表的单文件，可离线打开和转发，无需登录平台。

## 验收规则

- 标准存放在 `PerformancePlan.acceptance_targets`，创建正式运行时复制到 `PerformanceRun.acceptance_targets`。不放入节点的签名执行快照，不影响现有节点契约或单用户验证有效性。
- 后续修改计划不会改变历史运行的标准；旧计划、旧运行默认为空标准，不按新目标追溯判定。
- 达标条件：P95 ≤ 上限、错误率 ≤ 上限、平均请求吞吐量 ≥ 下限；每项比较仅使用有限有效数值。
- 运行及全部参与节点必须完整结束，且请求数有效。运行中为“等待运行结束”，未确认完整性或缺少相关指标时为“数据不足”，不能推断为通过。
- 在数据完整时，已确定有指标未达标则总体为“未达标”；不存在未达标但有缺失指标则为“数据不足”。
- 执行状态、性能验收与 AI 建议独立展示。单用户验证不进行性能指标验收。
- 新 AI 分析默认使用运行保存的标准。后端保留旧客户端显式传入分析目标的兼容行为；历史分析仍保留原目标，不覆盖运行验收结论。

## 轻量失败诊断

复用现有 `latest_metrics.failure_samples`，最多处理 20 条去重样本，按步骤、匿名节点、失败类别和唯一可确认的断言/提取规则定位。不能关联时标记未确认，不猜测位置。

模型输入仅包含索引、枚举、数值类型与空值特征，不包含原始 URL、名称、选择器、变量、期望/实际值、请求头、Cookie、令牌或异常消息。界面通过运行快照在本地补充步骤和节点名称。现有原始执行证据保持原行为。

去重样本数不代表失败请求次数，不能用来推算失败频率；没有服务端监控和完整调用链时，不宣称确定了服务端根因。下一步建议集中于使用单用户验证核对断言、提取和网络问题。

## HTML 导出

`GET /api/v1/projects/{project_id}/performance/runs/{run_id}/report.html`

- 下载沿用项目报告权限，只支持终态正式压测；不新增公开未鉴权查询接口。
- 包含运行配置、冻结验收、总体指标、吞吐量/P95/用户数趋势、接口和节点统计、失败样本摘要及已经完成的 AI 分析。
- 接口和节点以采集顺序编号展示，导出不包含原始请求/响应、完整执行快照、异常消息、日志或认证信息。
- 无外部 JS、CSS、字体、图片和平台 API 依赖；CSP 禁止脚本、联网、表单，文本经过 HTML 转义。
- 导出不发起 AI、重新验证或压测。文件仅反映导出时已有的结果；历史 AI 目标与运行标准不同时明确提示。

## 数据迁移与回退边界

迁移 `0010_performance_acceptance_targets` 仅新增两个 JSON 字段，默认空对象，不重写历史执行快照、指标和分析结果。

回退应用代码可保留新增列。若回退数据库迁移，会丢失新设置的验收标准，应先备份这两个字段。无需升级或重装发压节点。
