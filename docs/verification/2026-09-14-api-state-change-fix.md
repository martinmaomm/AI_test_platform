# API 同值更新问题修复与真实验收

结论：D-03 已完成定向修复和真实复测。原 CRUD 子场景 29 已补齐真实改名验证，保存为用例 14；调试执行 87 与三次独立执行 88、89、90 均通过。此结论不代表整份 API 验收清单全部通过。

## 根因与改动

原候选把新增、修改两个变量都写成 `qa_api_live_b_${uuid4}`。系统变量在单次执行内固定，两者实际相同；原断言只要求查询结果等于“新名称”，因此同值更新也被判为通过。

- 生成、修复共用的规则现在明确：系统变量每次执行只生成一次，反复引用不是反复调用函数；需要不同数据时使用不同阶段前缀或后缀，同时遵守文档字段格式和用户约束。
- 对需要真实状态变化的目标，要求先读取同一对象并提取实际旧值，再在操作后精确查询，既验证 `eq` 预期新值，也验证 `ne` 实际旧值；不能只凭接口成功宣称变化。
- 明确排除幂等、重复提交、保持原值等预期不变的场景。缺少可靠查询能力时说明证据不足，不编造路径或状态。
- 没有增加网站、接口路径、字段名或按钮名的关键词判断；没有改动运行器的变量作用域、账号保护或受保护断言审核。
