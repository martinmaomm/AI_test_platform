## 一句话结论

当前“从需求生成”会把 AI 输出直接写入正式测试用例库，但生成前无法确认上下文是否完整，生成后没有人工审核，也没有直接形成可执行自动化。

V2 将其改造成一条可追踪的草稿流水线：

```text
选择模块 → 资产预检 → 配置生成范围 → AI 生成草稿
        → 确定性校验 → 人工审核 → 事务导入
        → 按需继续生成 Python Playwright 脚本
```

用户选择的模块是强约束，AI 不得重新分配模块。生成结果在用户确认前不得进入正式测试用例库。

## 1. 背景与现状

### 1.1 当前实际流程

```text
用户选择项目
  ↓
从测试用例管理维护的 WebUI 模块树中选择模块
  ↓
输入可选的场景描述
  ↓
后端创建 Celery 任务
  ↓
检索项目知识库 Top 5 文档片段
读取所选模块下的页面名称和元素名称
  ↓
LLM 设计 6～8 条结构化测试用例
  ↓
LLM 再次进行结构化审核
  ↓
逐条写入 WebUITestCase
  ↓
用例没有 test_script_content，无法直接执行
  ↓
用户进入测试用例管理，再发起 AI 脚本生成
```

### 1.2 已确认的问题

1. 生成结果未经用户确认直接落库，容易污染正式用例库。
2. 保存过程没有覆盖整批数据的事务和幂等控制，失败后可能部分落库或重复导入。
3. 用户选择模块后，AI 仍会从全部模块中重新选择 `module_id`，最终归属可能漂移。
4. 页面承诺“所有需求与页面资产”，实际只使用项目级 RAG Top 5 和部分 UI 资产名称。
5. 模块的 `description`、`business_rules`，页面的 `url_path`，元素的 `action_type` 没有完整进入上下文。
6. “上下文完善度”只要选中模块就显示 100%，无法反映知识库、页面和元素是否齐全。
7. AI 审核主要验证输出结构，不能证明动作、元素和业务规则正确。
8. 页面无法选择模型，后端默认使用最新创建的启用模型，生成结果难以复现。
9. 任务只有临时 WebSocket 状态，刷新页面后无法恢复完整进度。
10. 生成完成后缺少明确的草稿审核、导入和继续生成脚本入口。
11. 模块接口失败时前端展示假模块，可能诱导用户提交无效模块 ID。
12. AI 输出使用未清理的 `v-html` 渲染，日志还会完整打印需求上下文，存在安全风险。

### 1.3 可复用能力

本次不推翻现有系统，继续复用：

- `WebUITestModule` 模块树及现有增删改查接口；
- `WebPage`、`WebElement` 页面元素资产；
- 项目知识库及 RAG 检索服务；
- `WEBUI_STEPS_MAPPING` 标准动作定义；
- Celery、Redis 和 WebSocket 基础能力；
- `WebUITestCase` 用例编辑和模块管理页面；
- 已实施的 WebUI AI 脚本生成 V2 流水线；
- Python Playwright 脚本契约、校验、执行和失败诊断能力。

## 2. 产品定位

### 2.1 页面定位

页面名称继续使用：`从需求生成`

副标题调整为：

> 根据业务模块、需求资料和页面资产生成测试用例草稿。审核导入后，可继续生成可执行的 Python Playwright 脚本。

该页面负责“测试设计”，不声称已经生成可执行自动化。只有脚本状态为 `ready` 的用例才能执行。

### 2.2 与“AI 脚本生成”的职责边界

| 功能 | 从需求生成 | AI 脚本生成 |
| --- | --- | --- |
| 输入 | 模块、需求、业务规则、页面元素 | 测试场景或已有测试用例 |
| 主要目标 | 生成可编辑的结构化用例草稿 | 生成可执行 Python Playwright 脚本 |
| 是否操作浏览器 | 否 | 是，只读探索阶段使用 MCP |
| 主要产物 | 标题、前置条件、步骤、预期结果 | `async def run(page)` 脚本 |
| 是否直接执行 | 否 | 脚本保存并通过校验后可执行 |

### 2.3 非目标

- 不把“从需求生成”改造成浏览器探索页面，探索职责仍属于 AI 脚本生成。
- 不在生成草稿后自动执行测试。
- 不强制每次生成后都继续生成脚本。
- 不在第一版接入外部需求管理系统。
- 不建设第二套模块、页面或元素体系。
- 不允许 AI 修改用户明确选择的模块。
- 不以模糊的百分比分数代替具体资产缺失项和校验结果。

## 3. 目标用户流程

### 3.1 第一步：选择模块

模块继续来自：

```text
WebUI 自动化 → 测试用例 → 左侧模块树
```

“从需求生成”页面增加：

- `管理模块`快捷入口，跳转 `/web-testing/test-cases`；
- 模块搜索和当前选择标签；
- 没有模块时的空状态和`创建模块`按钮；
- 不再提供接口失败后的假模块数据；
- 模块接口失败时明确显示“模块加载失败，请重试”。

模块在提交生成任务后不可由 AI 修改。后端必须使用请求中的 `module_id` 强制写入草稿和正式用例。

### 3.2 第二步：资产预检

选中模块后，页面展示上下文准备情况：

| 资产 | 展示内容 | 阻断规则 |
| --- | --- | --- |
| 模块信息 | 名称、描述、业务规则数量 | 模块不存在或无权限时阻断 |
| 需求资料 | 命中的知识文档数量和标题摘要 | 没有资料时警告，不强制阻断 |
| 页面资产 | 页面数量、页面名称、路径 | 没有页面时警告 |
| 元素资产 | 元素数量、按页面分组 | 没有元素时警告 |
| 当前模型 | 提供商、模型名称、启用状态 | 模型不可用时阻断 |

不再显示“上下文完善度 100%”。改为明确状态：

- `准备完成`：模块、模型可用，并有需求或页面资产；
- `资料较少`：可以生成，但标出缺失项；
- `无法生成`：模块或模型不可用；
- `加载失败`：资产接口异常，不能假装数据完整。

### 3.3 第三步：生成配置

生成表单包括：

1. 业务模块：必选，生成期间锁定；
2. 场景描述：可选，前后端统一限制 2000 字；
3. 用例范围：必选；
4. 用例类型：功能、异常、边界，可多选；
5. 目标数量：默认 6，允许 1～10；
6. 模型：必选，默认使用系统默认模型，不使用“最新创建模型”的隐式规则；
7. 知识库：只读显示是否可用和本次命中数量。

用例范围建议提供：

- `核心流程`：优先生成主流程和关键校验；
- `指定场景`：严格围绕用户描述；
- `模块覆盖`：根据现有需求资料生成代表性用例，不再使用“全量用例”这一无法验收的说法。

当用户选择“指定场景”时，场景描述必填。

### 3.4 第四步：生成草稿

生成后进入草稿审核区，不立即进入测试用例库。每条草稿展示：

- 用例名称；
- 用例类型和优先级；
- 需求来源摘要；
- 前置条件；
- 测试步骤；
- 预期结果；
- 确定性校验结果；
- 警告和阻断原因。

用户可以：

- 勾选或取消单条草稿；
- 编辑标题、前置条件、步骤和预期结果；
- 删除不需要的草稿；
- 重新生成全部草稿；
- 对校验失败项进行修改后重新校验；
- 查看本次生成使用的资料和模型。

第一版不实现“单条重新调用 AI”，避免任务状态和费用控制过度复杂；用户可手工修改单条或重新生成整批。

### 3.5 第五步：确认导入

只有通过硬性校验的草稿可以导入。点击`确认导入`后：

1. 前端提交最终选中和编辑后的草稿；
2. 后端再次执行完整确定性校验；
3. 使用数据库事务一次性保存；
4. 任意一条失败则整批回滚；
5. 使用生成记录和草稿键保证重复点击不会重复创建；
6. 返回实际创建、跳过和失败数量。

导入完成后提供：

- `查看已导入用例`；
- `继续生成脚本`；
- `返回继续创建`。

### 3.6 第六步：继续生成脚本

用户点击`继续生成脚本`时：

1. 选择已导入的用例；
2. 选择 WebUI 测试环境；
3. 选择模型；
4. 按需填写临时探索凭据；
5. 进入现有 AI 脚本生成 V2 页面和任务体系；
6. 每条用例拥有独立脚本生成状态，失败不会影响已导入的结构化用例。

第一版可以先实现“携带用例筛选条件跳转到测试用例管理”，再逐步增加批量生成脚本能力，避免一次并发启动过多 MCP 浏览器任务。

## 4. 上下文构建规则

### 4.1 模块上下文

必须包含：

- `module_id`；
- 模块名称；
- 模块描述；
- `business_rules`；
- 父模块路径，例如`权限管理 / 用户管理`。

模块上下文由后端根据 `module_id + project_id` 查询，不接受前端提交模块名称作为可信数据。

### 4.2 页面元素上下文

每个页面传入：

- 页面名称；
- `url_path`；
- 页面类名；
- 元素名称；
- 元素推荐操作类型 `action_type`。

不把完整 `pom_code` 或全部定位器原文发送给需求生成模型。需求生成只负责设计自然语言步骤，定位器和脚本由后续脚本生成流程处理。

### 4.3 知识库上下文

检索顺序：

1. 优先检索带当前 `module_id` 元数据的知识片段；
2. 没有模块级资料时，降级到当前项目资料；
3. 默认最多返回 8 个高相关片段；
4. 保存使用的知识文档 ID、片段 ID 和分数，不保存不必要的全文副本；
5. RAG 不可用时允许仅依据模块和页面资产生成，但必须向用户展示警告；
6. 不允许静默省略知识库故障后仍显示“资料准备完成”。

### 4.4 上下文快照

生成记录保存经过脱敏的上下文快照：

- 模块信息；
- 页面和元素摘要；
- 命中文档标识及分数；
- 用户生成配置；
- 模型配置 ID 和模型名称；
- 上下文构建版本。

快照用于刷新恢复、问题追踪和结果复现。不得保存 API Key、密码、Token、Cookie 或知识文档无关全文。

## 5. AI 生成与校验流程

### 5.1 推荐工作流

```text
build_context
    ↓
generate_structured_drafts
    ↓
deterministic_validate
    ├── 全部通过 → needs_review
    └── 可修复问题 → repair_once → deterministic_validate
                              ├── 通过 → needs_review
                              └── 失败 → needs_review（带阻断项）
```

不再使用“第二个 AI 审核节点直接宣布全部审核通过”。AI 可以进行一次受约束修复，但最终结论由确定性校验器给出。

### 5.2 结构化输出契约

Pydantic 模型改为严格枚举和长度约束：

- `priority`：`high | medium | low`；
- `category`：`functional | negative | boundary`；
- `action`：只能来自 `WEBUI_STEPS_MAPPING`；
- `module_id`：不由模型输出，后端统一注入；
- `title`、`description`、`expected_result`：必须非空并限制长度；
- `steps`：至少 1 步，`step_id` 连续；
- `target`、`value`：按动作定义验证是否必填；
- `source_refs`：记录需求或资产来源标识，不让 AI 填写任意数据库 ID。

### 5.3 确定性校验规则

硬性阻断：

1. 模块与生成记录不一致；
2. 动作不在标准动作表中；
3. 必填的目标元素或输入值缺失；
4. 不需要目标或输入值的动作却携带非法参数；
5. 步骤编号重复或不连续；
6. 标题、步骤或预期结果为空；
7. 类型、优先级或字段格式非法；
8. 发现疑似密码、Token、Cookie 或 API Key；
9. 草稿数量超过配置上限；
10. 导入请求中的项目、模块或生成记录权限不匹配。

警告项：

1. 目标元素无法在所选模块资产中精确匹配；
2. `goto` 路径没有对应页面资产；
3. 没有命中知识库资料；
4. 预期结果过于笼统；
5. 多条用例步骤高度重复；
6. 用例只覆盖正常流程，缺少用户选择的异常或边界类型。

警告允许导入，但必须明确展示；硬性阻断未解决前不能导入。

## 6. 数据模型设计

### 6.1 新增 WebUITestCaseGeneration

建议新增独立模型，避免把需求草稿任务塞入脚本生成记录：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | UUID | 前端和 WebSocket 使用的生成记录 ID |
| `project` | FK | 所属项目 |
| `user` | FK | 发起用户 |
| `module` | FK | 用户选择并锁定的模块 |
| `model_config` | FK/SET_NULL | 本次使用的 LLM 配置 |
| `status` | CharField | 当前生命周期状态 |
| `task_id` | CharField | Celery 任务 ID |
| `request_text` | TextField | 脱敏后的用户场景描述 |
| `generation_scope` | CharField | 核心、指定或模块覆盖 |
| `case_categories` | JSONField | 用户选择的用例类型 |
| `target_case_count` | PositiveSmallInteger | 目标数量 |
| `context_snapshot` | JSONField | 脱敏上下文快照 |
| `draft_test_cases` | JSONField | 当前草稿 |
| `validation_report` | JSONField | 阻断项和警告项 |
| `created_case_ids` | JSONField | 导入后创建的用例 ID |
| `error_code` | CharField | 稳定错误编码 |
| `error_message` | TextField | 用户可读失败原因 |
| `created_at/updated_at/completed_at` | DateTime | 生命周期时间 |

状态建议：

```text
created
context_building
generating
validating
repairing
needs_review
importing
imported
failed
cancelled
```

### 6.2 WebUITestCase 来源关联

为 `WebUITestCase` 增加：

- `source_requirement_generation`：可空外键；
- `source_draft_key`：可空字符串，用于单条草稿幂等识别。

增加普通复合唯一约束：

```text
(source_requirement_generation, source_draft_key)
```

MariaDB 对包含 `NULL` 的普通唯一约束允许多条手工用例，因此不需要条件唯一约束，避免再次触发 MariaDB 不支持条件约束的警告。

脚本来源继续由 `script_source` 表示；需求生成来源与脚本生成来源是两个不同维度，不复用或覆盖 `generation_metadata`。

### 6.3 兼容策略

- 现有 `WebUITestCase` 不需要回填生成记录；
- 旧用例保持原模块、步骤和脚本状态；
- 旧生成接口在迁移期保留，但前端切换后不再暴露入口；
- V2 稳定后再删除旧智能体的自动落库节点；
- 数据库迁移只增加模型和字段，不删除历史字段。

## 7. API 与异步任务设计

### 7.1 API 建议

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/web-testing/test-case-generations/context/` | 获取模块资产预检结果 |
| `POST` | `/web-testing/test-case-generations/` | 创建并启动生成任务 |
| `GET` | `/web-testing/test-case-generations/{id}/` | 获取任务、草稿和校验结果 |
| `POST` | `/web-testing/test-case-generations/{id}/validate/` | 校验用户编辑后的草稿 |
| `POST` | `/web-testing/test-case-generations/{id}/import/` | 事务导入选中草稿 |
| `POST` | `/web-testing/test-case-generations/{id}/cancel/` | 取消运行中的任务 |

所有接口必须同时校验用户、项目和生成记录权限，不能只依赖前端传入的项目 ID。

### 7.2 WebSocket 与恢复

- 每条消息必须包含 `generation_id`、`task_id`、`stage` 和时间戳；
- 前端只处理与当前生成记录匹配的消息；
- 不继续把同一用户的所有任务混在一个无任务过滤的消息流中；
- WebSocket 只负责实时体验，`GET generation detail` 是最终真实来源；
- 页面刷新后根据路由或本地保存的 `generation_id` 恢复；
- WebSocket 中断不改变任务本身的执行状态；
- Celery Worker 重启后，数据库仍能展示任务最后状态和草稿结果。

### 7.3 幂等与并发

- 同一生成记录只允许一个运行中的 Celery 任务；
- 重复点击创建时，前端禁用按钮，后端仍需防重；
- 导入接口通过生成记录状态、草稿键和唯一约束防止重复；
- 导入期间使用 `select_for_update()` 锁定生成记录；
- 已导入记录再次请求时返回原创建结果，不重复创建用例；
- 取消和完成事件必须处理竞态，以数据库最终状态为准。

## 8. 前端页面设计

### 8.1 页面区域

V2 页面建议分为四个区域：

1. **模块与资产**：模块选择、管理入口、资产统计和缺失提示；
2. **生成配置**：范围、类型、数量、模型和场景描述；
3. **执行进度**：上下文构建、生成、校验和修复时间线；
4. **草稿审核**：测试用例卡片、编辑、选择、校验和确认导入。

不再把完整流程伪装成聊天窗口。聊天式流式输出可以放在可折叠的“AI 生成详情”中，主要操作应围绕配置和草稿审核。

### 8.2 完成状态

生成完成后显示：

```text
生成 6 条草稿
通过 4 条
有警告 2 条
阻断 0 条
```

草稿按状态筛选：全部、可导入、有警告、需修改。

导入完成后显示实际用例链接和后续操作，不只弹出“任务完成”。

### 8.3 安全渲染

- 默认使用 Vue 文本插值和结构化组件渲染 AI 内容；
- 如必须展示 Markdown，使用受控 Markdown 解析器并清理 HTML；
- 禁止把模型原文直接交给 `v-html`；
- 错误信息不展示 Python 堆栈、数据库路径或模型 API 响应原文；
- 技术信息进入开发日志或折叠诊断区。

## 9. 日志与可观测性

### 9.1 业务日志

记录：

- `generation_id`、`task_id`、用户 ID、项目 ID、模块 ID；
- 模型配置 ID、提供商和模型名称；
- 当前阶段、耗时、草稿数量；

- 校验阻断项、警告数量；
- 导入创建、跳过和失败数量。

### 9.2 禁止记录

- 模型 API Key；
- 用户密码、Token、Cookie；
- 完整知识文档内容；
- 完整 LLM 请求和响应；
- 浏览器登录凭据；
- 未经脱敏的用户输入。

开发阶段如需要排查提示词，使用显式调试开关并执行脱敏，不能默认打印“喂给大模型的完整需求内容”。

## 11. 分阶段实施计划

### 阶段一：数据基础与资产预检

1. 新增 `WebUITestCaseGeneration` 和用例来源关联字段；
2. 增加迁移和模型测试；
3. 实现模块上下文构建器；
4. 实现资产预检接口；
5. 前端增加模块管理入口、空状态和资产统计；
6. 删除假模块降级逻辑；
7. 前后端统一场景描述 2000 字限制。

验收标准：用户能看见模块来源、资产数量、缺失项和当前模型，模块加载失败时不会出现假数据。

### 阶段二：草稿生成与确定性校验

1. 重构智能体输入和严格结构化输出；
2. 强制绑定用户选择的模块；
3. 增加模型选择并传递 `model_config_id`；
4. 实现确定性校验器；
5. 最多执行一次 AI 修复；
6. 保存生成记录、上下文快照、草稿和校验结果；
7. 移除生成任务中的自动落库节点。

验收标准：AI 无法修改模块；非法动作、缺失参数和敏感信息会被阻断；生成结束只产生草稿，不产生正式用例。

### 阶段三：草稿审核与事务导入

1. 前端展示结构化草稿卡片；
2. 支持选择、编辑、删除和重新校验；
3. 实现确认导入接口；
4. 使用事务、记录锁和唯一约束保证一致性；
5. 返回导入结果和用例链接；
6. 增加重复提交、部分失败和权限测试。

验收标准：未确认不落库；失败整批回滚；重复点击不会重复创建；只导入用户选中的草稿。

### 阶段四：任务恢复与脚本生成衔接

1. 所有事件携带生成 ID 和任务 ID；
2. 前端按任务过滤 WebSocket 消息；
3. 页面刷新后通过生成记录接口恢复；
4. 增加取消和失败恢复；
5. 导入后提供“查看用例”和“继续生成脚本”；
6. 第一版先跳转到现有单用例脚本生成入口；
7. 批量脚本生成作为后续独立迭代。

验收标准：刷新页面不丢任务；多个标签页任务不串线；导入用例可以顺利进入现有脚本生成 V2 流程。

### 阶段五：安全、兼容与清理

1. 移除未清理的 `v-html`；
2. 删除完整 RAG 内容和完整提示词日志；
3. 补充安全脱敏测试；
4. 保留旧接口兼容但隐藏入口；
5. 完成真实业务场景验收后删除旧自动落库逻辑；
6. 更新项目 README 和功能说明。

验收标准：前端不执行模型 HTML；日志中不出现凭据和知识全文；旧数据和现有脚本生成流程不受影响。

## 12. 测试计划

### 12.1 后端单元测试

- 模块、父模块路径、业务规则上下文；
- 页面路径和元素摘要构建；
- RAG 可用、无结果和故障降级；
- 模型配置权限和停用状态；
- 标准动作、目标和值参数校验；
- 元素存在性和页面路径警告；
- 敏感信息检测；
- 草稿数量、步骤编号和字段长度；
- 模块强绑定；
- 上下文快照脱敏。

### 12.2 API 与权限测试

- 无项目权限不能预检、生成、查看或导入；
- 模块不属于当前项目时拒绝；
- 模型不存在或已停用时拒绝；
- 生成记录只能由有权限的项目成员访问；
- 导入时再次校验前端编辑内容；
- 重复导入返回原结果；
- 事务中任一用例失败时全部回滚；
- 取消、失败、完成竞态状态正确。

### 12.3 Celery 与 WebSocket 测试

- 任务阶段正确写入数据库；
- 消息包含生成 ID 和任务 ID；
- 不同生成任务消息不会串线；
- WebSocket 不在线时任务仍正常完成；
- Worker 异常时生成记录进入可理解的失败状态；
- 页面刷新后能通过接口恢复最终草稿。

### 12.4 前端测试

- 无模块、无页面、无元素、无知识库和模型不可用状态；
- 管理模块快捷入口；
- 2000 字限制；
- 草稿选择、编辑、删除和校验；
- 阻断项禁止导入；
- 导入成功后的链接和脚本生成入口；
- 多任务消息过滤；
- AI 内容不使用未清理 HTML 渲染；
- `npm run build` 通过。

### 12.5 真实业务验收场景

1. 登录模块有知识库、页面和元素，生成核心正常流程；
2. 用户模块没有知识库但有页面资产，生成并展示资料不足警告；
3. 空模块生成时展示缺失资产，不伪装准备完成；
4. AI 返回不存在的动作，被确定性校验阻断；
5. AI 返回其他模块 ID，最终仍强制使用用户所选模块；
6. 生成 6 条草稿，只选择 3 条导入，正式库只新增 3 条；
7. 重复点击导入，正式库不产生重复用例；
8. 刷新生成页面，任务和草稿能够恢复；
9. 导入后从测试用例管理继续生成脚本；
10. 脚本生成、保存和执行沿用现有 V2 流程并正常工作。

## 13. 风险与控制

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| 数据库迁移失败 | 页面无法使用新记录 | 增量迁移、备份、迁移前后检查 |
| 旧流程与新流程并存 | 产生两套行为 | 前端只暴露 V2，旧接口只作短期兼容 |
| RAG 结果不稳定 | 生成质量波动 | 保存来源快照、显示命中资料、允许无 RAG 降级 |
| 模型结构化输出兼容性差 | 任务失败 | 严格解析、一次有限修复、明确失败状态 |
| 草稿编辑后绕过校验 | 非法数据入库 | 导入接口必须重新校验，不信任前端状态 |
| 重复提交 | 重复用例 | 记录锁、幂等草稿键、数据库唯一约束 |
| WebSocket 断开 | 用户误以为任务失败 | 数据库记录为准，接口恢复，WebSocket 只作实时增强 |
| 批量脚本生成消耗过大 | Worker 和 MCP 资源拥堵 | 第一版只跳转单用例生成，批量能力单独设计限流 |

---

## 14. 回滚方案

1. 新数据库迁移只增加表、字段和约束，不删除旧数据；
2. 前端 V2 页面异常时可临时切回旧生成页面；
3. 旧接口保留到真实业务验收通过；
4. V2 生成失败不会影响现有测试用例和脚本；
5. 回滚前端和任务路由时，新生成记录可以保留，不必删除；
6. 如需回滚数据库迁移，先确认没有正式依赖新来源关联的数据；
7. 不通过删除用户用例的方式回滚功能。

## 15. 完成定义

以下条件全部满足才视为 V2 完成：

- 用户能明确知道模块从哪里维护；
- 页面能展示真实资产准备情况；
- 用户可以选择生成范围、数量、类型和模型；
- 用户选择的模块不会被 AI 修改；
- AI 结果先成为草稿，未经确认不进入正式库；
- 草稿经过确定性校验，阻断项不能导入；
- 导入具备事务、权限和幂等保障；
- 刷新页面可以恢复任务和草稿；
- 生成记录能够追踪模型、上下文来源和创建的用例；
- 导入后可以进入现有 AI 脚本生成 V2；
- 前端无假模块和未清理的模型 HTML；
- 日志中不记录凭据、知识全文和完整提示词；
- 后端相关自动化测试、Django 系统检查和前端生产构建通过；
- 至少完成一条真实业务模块的“需求 → 草稿 → 导入 → 脚本生成”人工验收。

## 16. 建议实施顺序

建议严格按以下顺序推进：

1. 阶段一：先建立生成记录和资产预检；
2. 用户验收模块来源与资产展示；
3. 阶段二：实现草稿生成和确定性校验；
4. 使用真实模块验证生成质量；
5. 阶段三：加入人工审核和事务导入；
6. 阶段四：补齐恢复与脚本生成衔接；
7. 阶段五：完成安全清理、兼容移除和文档更新。

不建议一次提交全部阶段。每个阶段独立提交、独立测试和独立验收，可以降低数据库、模型调用和前端状态同时变化带来的排查难度。
